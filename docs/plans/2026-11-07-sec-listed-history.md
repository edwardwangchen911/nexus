# SEC listed-history 正常入口与前瞻覆盖实施

依据：2026-11-06 用户授权修复 NVDA 覆盖缺口，以及既有产品评审 R1/R2。
目标是使已安装 SEC 计划获得可验证的后续覆盖，不追认原未知区间。

## 固定边界

- 保留 v1 原件、哈希、计划、检查、事件与解释；不按 filingDate 推定可用时点。
- 正常入口只取父 current 原件明确列出的固定 SEC 路径。本切片最多一个历史分片，
  合并来源（含 directory 与全部 receipt）总字节不超过 8 MiB、总记录不超过 10000、支持事件不超过 1000。
- 公开 HTTP 采集链共享原 60 秒截止；身份读回和后续 import 沿用原事务/存储边界，
  不宣称整个命令 60 秒有界。导入确认不明按原 capture 身份只读核对、不重试。
- 原请求单次、原时限、不重试、不截断；缺片、列表变化、超限、冲突不能 complete。
- TXT 是索引元数据事实，不能直接进入既有 HTML 正文解释或被过滤后声称完整。
- 业务扫描 8 秒、共享 13 美元、未知预留、执行锁和普通 Worker 停用不变。

## 实施及证据

- [x] 新版本 parser 与 capture，保留 listed 分片、实际收件与父闭合原件，正常
  collect/import/inspect 可往返验证。新增来源身份与 v1 隔离，接线完成前不得让
  v1 consumer 默默消费新格式。覆盖真实原件形态、TXT、错误来源、缺片、重复、
  冲突、计数、边界、来源变化、迟到入库与非空旧数据兼容。
- [ ] 不可变的前瞻比较起点绑定原 plan/baseline/hash、新完整 capture/hash、政策版本
  及实际生效时间。首次旧档不派发，原来可独立确认的 recent 新项不被吞没；
  C1→C2 才证明相对 C1 的完整 false。B0→C1 未知永久可见；并发/重复/提交不明
  不重复建立起点，不反复 bootstrap 消除差异。
- [ ] consumer、API、页面同时消费新起点；后补旧日期 accession 仍为新增收录，
  同 accession 变更/缺页/stale 保持 unknown。未知格式正文明确拒绝，索引事实保留。
- [ ] 当前冻结计划的隔离 producer→outbox→consumer→单股接替完整链，正常模型和
  通知替身、预算/未知/并发保护；其他两股不研究，不向真实设备发送消息。
- [ ] 定向终审、相关本地验证、兼容回滚镜像与安全部署，沿自然入口只读验收。
  远端 CI 不阻塞本地功能验收；合并仍遵守分支保护。

正常采集/读回是第一交付切片，不代表监控、通知或接替全目标已完成。

## 第一切片验证（2026-11-07）

正常来源入口与新旧 reader 隔离已实现，尚未部署、未接入正式监控。

新增及相关 32 项通过。六个源码模块 Mypy、Ruff 和 diff 检查通过。
未来收件拒绝的既有反例保留；已取得材料的夹具改用明确过去时间，
避免宿主与测试数据库毫秒时钟偏差，没有改生产时点门禁。

本轮冻结公开原件在一次性恢复库里经过正常 collect/import/inspect，
HTTP 使用本地替身和明确合成回执；248 条目标记录含 11 条 TXT 完整保留，
重复导入身份稳定，旧业务事实未变，隔离库已清理。它不证明 live 覆盖恢复。
R3 没有确认的 P1；R4 已关闭两项 P2，无新增具体 P1/P2。新版本比较起点、
消费者及页面、整链受控验收与兼容维护镜像仍待后续切片。
