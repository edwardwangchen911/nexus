# 请求内研究准备复用

**目标：** 不调用真实模型，以已有冻结归档证明输入和动态拒绝合同不变，减少同一纯研究请求的重复计算。

**方案依据：** 2026-10-22 已回收并源码核验的 Chat 评审（nexus-ci-and-research-parallel-review-20261022-01），以及随后用户明确实施、验证、合入部署授权。评审要求“复用同一请求内已验证的不可变证据和纯编译结果，保留每次领取、执行前的动态准入检查”。股间保持串行，不能缓存“预检通过”。

## 实施边界

- `dispatch_pure_research_request` 为唯一启用边界，覆盖其原有正常执行及清理；请求退出、异常或取消均清空并停用缓存，嵌套请求分离。普通研究及没有 scope 的消费者保持原路径。
- 身份解析复用原 `identity_parse_scope`：每次仍读原件、回执、当前映射和绑定；仅精确实际原文哈希相同的成功纯解析可复用，退出清空。
- `project_staged_payload` 仅缓存完整有序 JSON 与两个投影开关决定的成功结果，保留字典和引用顺序。只接受安全普通 JSON 值，返回深复制；最多32项、序列化结果总计8MiB。其他输入继续原路径。
- token 编码仍逐次验证模型、tiktoken版本、实际词表及编码器工厂；仅校验通过后复用实际 encoder 对象、模型和精确 wire 哈希的成功计数，最多128项。词表失效按原规则回退字节计数，不缓存失败或完整 allowance；schema/指令/reserve 每次重算。
- 不缓存 `_committee`、`_inputs`、容量池或动态状态。新委员会的 deadline、session、dispatch guard、claims、usage 不共享；原字段、用途、预算、调用数、deadline、失败收尾和正式准入不变。不增加依赖或迁移。

## 风险和回滚

缓存仅在当前进程的一次请求内存活，字节上限是序列化值大小，不宣称等于Python RSS。代码变更可退回兼容0084的已验证镜像，不降数据库schema、不回写旧研究。原件及动态检查未减少，若这些占据主要剩余耗时，停止扩大缓存；不以跳过验证追求提速。真实调用数量为零，唯一历史完成三股及未知预算保持。
