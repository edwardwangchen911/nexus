# NEXUS Agent 模拟交易与策略进化路线图

**状态：** 第一阶段已完成真实 no-trade 闭环和同日多决策验收；连续运行与真实订单路径待推进

**核查日期：** 2026-09-16

**适用范围：** Mac 本地、内部模拟优先、真实账户只读、实盘关闭

## 一页结论

NEXUS 的主线不是让固定策略长期替 Agent 作决定，也不是继续建设独立 Research Shadow。
正确目标是：

> 多源真实证据进入研究 Agent → Agent 形成可追溯的模拟买卖意图 → 确定性代码计算数量、执行硬风控和模拟成交 → 账本与绩效记录结果 → 与保持不动、固定基线和市场基准比较 → Agent 基于未来结果复盘并产生下一版本 → 新旧版本继续并行模拟验证。

Agent 是投资判断主体；确定性代码是资金、风险和执行主体；用户是未来实盘授权主体。模拟成绩
不能自动解除 `execution_locked=true`。

项目不是缺少数据或从零开始。复星、Alpaca、嘉信、SEC、FRED/ALFRED、FMP、SSGA 和交易
日历均已有不同程度的真实代码、归档、持久化和 Agent 消费证据。截至 2026-09-15，第一阶段
最小闭环及同日多决策基数已经落到 `main@fc3c019b`：真实 Agent Job、确定性 sizing、硬风控、
Schwab 决策报价、按需执行窗口、API/BFF/`/paper` 回读和前台五分钟循环均已有正常产品入口，
默认关闭且始终保持 `execution_locked=true`。

真实业务库已保存 10 个 Agent 周期，其中 5 个以 `NO_ORDER_REQUIRED` 完成、5 个诚实停在
`unavailable`。最近两个不同五分钟槽分别形成独立周期、Job/Run/Output 和 Agent decision，均经过
硬风控并以 `sizing_action=none` 完成。该证据证明真实 no-trade 路径和同日多决策可用，但不证明
真实订单、成交和账本变化路径已经发生；当前仍是 0 笔 Agent 订单、0 笔 Agent 成交。

所以准确进度是：**主闭环已经跑通诚实 no-trade 路径，不是从头开始；下一阶段是积累连续运行与
订单能力的真实证据，持续完善已有对照后再进入 Agent 进化，而不是继续扩建框架。**

## 最终产品目标与职责边界

### Agent 决定什么

- 在已准入股票范围内选择关注和操作标的；
- 输出买入、减仓、退出、持有或暂不操作；
- 给出期限、置信度、证据、反方观点和失效条件；
- 结合模拟结果复盘证据质量、判断错误和决策行为；
- 产生可版本化的新提示、记忆、工具策略或候选决策逻辑。

### 确定性代码决定什么

- 标的身份、数据时点和用途是否合格；
- 目标仓位和订单数量；
- 现金、可卖数量、集中度、换手、回撤和其他硬风控；
- 模拟成交、滑点、费用、部分成交、账本和幂等；
- 候选版本的样本外比较、晋升门槛和回退；
- 任何模拟结果都不能自动获得实盘权限。

### 用户决定什么

- 是否启用券商正式模拟盘等外部写入；
- 是否修改资金、股票池、硬风控和运行停止条件；
- 是否进入实盘；
- 实盘阶段仍逐笔确认订单。

这套分工既保留 Agent 的投资判断能力，也避免 LLM 直接计算资金、绕过风控或调用券商。

宏观和汇率证据不是交易价格，必须保留发布时点、实际可用时间与 vintage，

## 已有能力应该怎样复用

### 研究 Agent

现有八类研究角色、证据冻结、正反观点、审计、失效条件和 `watch/none` 机制保留。单股
`ResearchIntent` 已能表达 `buy_candidate`、`reduce_candidate`、`hold` 和 `watch`，不需要重写
研究系统，也不需要先增加更多角色。

### Portfolio Agent

现有 Portfolio Agent 绑定当前组合、诊断和确定性情景，但只能输出 `explore_adjustment` 或
`observe`。它目前是解释和审核层，不是完整模拟决策者。后续应补最小组合级交易意图，而不是
推倒现有合同或让模型直接输出订单数量。

### `baseline_v1`

固定基线策略继续保留，但职责改为：

- Agent 的对照组；
- 受控比较与模拟基础设施运行探针；
- 衡量 Agent 是否产生增量价值；
- 保留确定性策略历史和可重复结果。

它不再冒充 Agent 的投资决策，也不在 Agent 失败时自动接管交易；Agent 结果不可用时不产生新的
Agent 模拟订单。

2026-09-15 进一步核对确认：现有 registered forward 仍强制 raw-only `source_policy_v2`，真实
provider 特征读取也因价格/成交量单位合同未建立而只接受 fixture。补齐历史日线不能越过这些门禁。
因此本轮保留 baseline 的历史策略和页面占位，但暂缓前向执行；不为补齐一行对照新增政策、迁移或
比较账户。重新启动条件见 `docs/superpowers/specs/2026-09-15-baseline-forward-comparison-design.md`。

### 内部模拟与策略进化

账户、风控、订单、部分成交、账本、绩效、幂等、champion/challenger、样本外比较和晋升代码
全部优先复用。当前需要连接和真实运行，不需要第二套账本、第二套注册表或第二个执行系统。

## Research Shadow 的正确位置

Research Shadow 不是独立交易系统。它只代表同一决策时点下的反事实对照：

```text
Agent 模拟决策
  ├─ 实际模拟路径：执行 Agent 意图
  ├─ 对照一：hold_current
  ├─ 对照二：baseline_v1（当前 unavailable，暂缓前向执行）
  └─ 对照三：合适的市场基准
               ↓
          统一绩效与归因
```

因此不继续建设专用评价版本、通用复权 vintage、独立政策体系和独立页面。先产生模拟决策和成交，
再由现有绩效系统计算对照。缺价或公司行动证据不足时，该比较明确 unavailable。

## 2026-09-13 历史五个断点（第一阶段接线现已完成）

### 1. Agent 意图没有进入模拟盘

当时已有单股研究方向和组合情景解释，但没有一个最小合同把 Agent 的标的、方向、期限、置信度、
证据和失效条件连接到现有 `ForwardStrategyDecision` / 风控 / 模拟执行。

### 2. 模拟价格用途尚未获准

当时代码明确保持 paper order、paper execution 和 paper performance 的真实价格 authority 为
不可用。后续要求是新增一份最小、不可变、用途限定的模拟价格政策；不能修改历史政策开关，
也不能把展示可用误认为成交可用。

### 3. 完整模拟成交窗口尚未形成

Alpaca 的接线和覆盖较广，但当时的 1 分钟数据不连续；嘉信的时点和 bid/ask 更明确，但只有单标的
短窗口；复星数据较多，但部分盘口、时点和用途合同未完整统一。当时的技术方案要求选择一条能形成完整
五分钟窗口的现有路径，不建设自动多源 fallback。

### 4. 正常产品运行编排未启用

当时真实 Agent、Provider Jobs、模拟调度和 Web 没有联合运行。不能用单测、fixture 或旧容器
代替正常入口验收。

### 5. 评价与进化没有模拟事实可消费

当时进化代码已存在，但没有订单、成交和有效绩效记录。必须先形成模拟事实，再讨论 Agent 是否改进；
不能只生成复盘文字或用同一段数据同时优化和验收。

## 后续最小迭代顺序

### 第一阶段：一次 Agent 驱动的内部模拟闭环（已完成 no-trade 真实验收）

**用户可见结果：** 能在 API/页面看到同一条“证据 → Agent 判断 → 仓位计算 → 风控 → 模拟订单
与成交或合理不交易 → 账本”的记录。

只做：

1. 从现有正式身份和已有数据中生成一个有界、可机器校验的 Agent 候选范围；
2. 复用现有研究结果，让 Agent 输出最小组合级交易意图；
3. 由确定性代码把方向转换为目标仓位和数量；
4. 新增最小模拟价格用途政策，并接入一条已有盘中来源；
5. 复用现有风控、订单、成交、账本和绩效服务；
6. 在现有组合页面/API 显示完整链路，不新建独立产品页。

真实 Agent 可以合理选择持有或不交易，不能为验收强制制造订单；受控测试必须覆盖买入、卖出、
拒绝、部分成交和幂等，真实案例则如实接受其结果。

### 第二阶段：连续模拟与统一对照（进行中）

**用户可见结果：** 每个交易日能看到数据更新、Agent 是否决策、订单状态、组合变化，以及相对
`hold_current` 和 SPY 市场基准的差异。`baseline_v1` 保留稳定 unavailable 状态，但其真实前向
价格用途合同暂缓，不作为本阶段完成前置。

每天可以更新证据和评价，但不要求 Agent 每天强行交易。先固定资金、候选范围、决策时点、最大
换手和停止条件，再启用本地调度。断线或结果未知时先查持久化事实，不更换幂等键重发。

### 第三阶段：Agent 复盘与版本进化（未开始）

**用户可见结果：** 每个 Agent 版本为什么被保留、淘汰或继续观察都有证据。

改进对象可以包括提示、记忆摘要、工具使用、证据权重、异议处理和候选决策规则。旧版本保持
冻结；训练和样本外窗口分离；新版本先与旧 Agent、固定基线和保持不动并行模拟。只有收益、
回撤、成本、稳定性和数据完整性共同通过预定门槛，才能成为下一版模拟冠军。硬风控不由 Agent
修改。

### 第四阶段：券商正式模拟盘（未开始）

在内部模拟稳定后，用同一意图和风控结果接入券商正式模拟账户，验证订单生命周期、回报、对账、
断线恢复和本地模拟偏差。该阶段属于外部写入，启用前单独授权，不与内部模拟第一阶段并行建设。

### 第五阶段：用户决定是否进入实盘（未开始）

只有内部模拟、样本外验证、券商模拟、费用和异常恢复积累足够证据后，才提交实盘评估。系统无权
自行解锁，实盘订单继续逐笔人工确认。
