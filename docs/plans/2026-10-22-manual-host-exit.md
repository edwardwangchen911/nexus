# 宿主退出审计与立即下一轮准入

## 问题与范围

正常纯研究宿主退出后仍保留30秒内心跳，新宿主写入新心跳后被误判为两个活跃宿主。
本切片新增精确退出事实并保留心跳审计；不改变研究并发、正式决策、模型预算、Job/lease
或未知用量的准入规则。两股并行候选单独保留，不能将本修复当作并行真实验收完成。

采用已批准的 `nexus-research-host-exit-review-20261022-01` 方案：新增0085只追加退出表，
绑定原心跳主键、身份、版本与末次心跳，退出时刻由数据库产生。退出记录表示本地派发和
相关任务已结束，不表示远端调用、研究结果或账务已经确认。

## 写入、读取与兼容

正常入口先收完本地worker，取消并等待keepalive，仍持flock时提交退出事实，最后释放锁。
SDK清理未确认时不写正向退出证明；退出失败保留原业务错误，成功研究不重标失败，返回
固定 `MANUAL_HOST_EXIT_UNCONFIRMED`，不得以新研究重试探测。

数据库锁定原心跳核验退出；旧快照通过不改变字段值的父行UPDATE产生MVCC冲突，防止
RR/Serializable旧快照复活宿主。迟到心跳被拒。准入、维护和状态读只排除精确退出实例；
历史取证保留旧心跳，未知用量、预留、lease/fence仍按原合同独立判断。

迁移只增加表与窄触发器，保留0020原审计约束。空表可在无活跃写者时降回0084；存在
退出事实则拒绝降级，不能删除审计。回滚应用需兼容0085或在没有退出记录时按验证流程
退回0084；旧代码不理解退出事实时可能保守拒绝立即续跑。

## 验证

原正常入口连续准备先RED，修复后同一30秒窗口内第二轮完整三股准备及未调用收尾通过，
旧心跳保留。覆盖身份错绑、伪造时间、不可变、双向RC竞争、RR/Serializable旧快照、
退出回滚/幂等、SDK清理取消、原错误保留、未知预算/lease仍阻断下一轮以及Provider无新
表权限仍能写自己的心跳。新增PG测试纳入必需CI清单。真实模型验收仍待后续并行候选交付。

额外完整Provider历史拓扑测试发现0070的既有 `economic_native_cycle_bound` 未进入其
精确预检清单，属于主线既存缺口；本修复没有放宽预检或夹带经济周期/权限变更。

## 集中评审定向修正
