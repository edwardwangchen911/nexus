## 2. 对象标识与版本语义

以下是演示展示别名，不要求更改现有持久化 ID、引入新编号系统或迁移历史数据。界面始终同时显示对象类型与标识，技术实现复用稳定的现有标识并保留完整值入口。

| 对象 | 本基线显示 | 关系与限制 |
| --- | --- | --- |
| 模型组合 | 模型组合 M1 | 单一内部模拟组合；不是新建账户指令 |
| 当前目标 | 目标 V7 · 生效 | 当前唯一生效目标，内容不可原地修改 |
| 新目标提案 | 提案 PROP-008 · 未生效／等待重新校验 | 替代概念图中的 P8；不是目标版本 V8，也不是计划 |
| 当前调整计划 | 调整计划 PLAN-007 · 部分完成 | 替代概念图中容易混淆的 P7；始终归属目标 V7 |
| 原订单 | 订单 ORD-007-01 | PLAN-007 下的 AAPL 模拟买入订单，历史归属不随新目标变化 |
| 原取消请求 | 取消请求 CXL-007-01 | 针对 ORD-007-01 的既有请求；核对必须锁定此请求 |

旧计划完成或确认取消、相关占用结清或释放、订单与实际组合核对一致且不存在未知结果后，PROP-008 才可按最新实际状态、政策与证据重新校验。满足生效条件时才生成新目标版本 V8 并替代 V7；不预先创建“待生效 V8”。如果复核无合法目标变化，继续使用 V7，不为运行次数制造版本。

页面默认不用裸 P7/P8，也不用“待生效”替代“未生效／等待重新校验”。历史记录可保留原始标识，但须带对象类型及对应关系。生效条件检查不能由前端禁用按钮代替。

首次尚无目标时写“尚未建立目标”；合法目标建立后、首笔模拟成交前写“首次目标建立”或“首次组合启动”。目标生效、计划建立、首笔成交均不得单独称为“完成建仓”。

| 项目 | 金额 | 含义 |
| --- | --- | --- |
| 计划形成时买入需求 | $2,000 | 确定性差额计算，不是 Agent 报单 |
| 风控获准金额 | $1,500 | 演示约束为换手限制；并非用户批准的新阈值 |

结果未知期间上述实际值是“最近已确认快照”，须同时显示快照时点与未知范围，不冒称即时最终余额。未确认的可能成交不得乐观计入持仓；未成交卖出所得不得预支。

## 4. 两个主界面的结构基线

### 4.1 decisions：组合决策详情

保持已选结构，按以下顺序组织：

1. 紧凑标题、内部模拟/真实只读边界、对象标识与数据时点。
2. 明确阻断结论：“提案 PROP-008 未生效；目标 V7 继续生效。”副文指出 PLAN-007 部分完成、原取消请求结果未知、预留尚未释放。主入口“查看调整计划”。
3. 简短“本轮组合取舍”，明确标签“Agent 原始判断”；包含选择、替换依赖与现金原因，不混入配置数值。
4. 目标对照表，以 V7 为当前权威列，PROP-008 为未生效对照列；继承项、不更新有效期、明确退出、拟纳入与确定性配置来源就地注明。实际列带独立时点，只用于对照，不替代目标。
5. 当前计划的风控与执行摘要：明确“PLAN-007 / V7”，避免将旧计划 AAPL 缩减误贴到 NVDA 提案上；提案的准入状态单独展示。
6. 政策依据、判断范围、证据/反方证据、研究有效性及版本关联按需展开。缺失或过期影响准入的结论不可藏进折叠区。

生效目标与未生效提案不共用一个无标题的“目标”数值。完整提案必须包含继承项及现金，不能只列新候选。重复观点不显示累计加仓；无变化继续引用原版本。

### 4.2 paper：调整计划主区域

顶部明确“调整计划 PLAN-007 · 目标 V7”，同时显示“部分完成”“取消结果未知”“预留 $500 未释放”；不能用单一成功/失败徽标覆盖三个维度。

主区域以执行时间线为轴；右侧“核对原操作结果”面板；下方金额、持仓及现金核对表。返回链接指向原组合决策，不跳转为最新提案的执行结果。

以下为演示时间顺序，不规定通用技术事件结构；实际页面采用事实时间，并显示完整日期与 UTC，不制造缺失时间：

| 演示时刻（2026-09-18 UTC） | 独立事件 | 只证明什么 |
| --- | --- | --- |
| 09:00 | 目标 V7 生效 | 目标成为唯一生效版本；不证明已有计划、订单或成交 |
| 09:05 | 调整计划 PLAN-007 建立，关联 V7 | 计划存在；占用金额须另外依据订单/预留事实，不能由建立事件推定 |
| 10:30 | 硬风控缩减 AAPL 需求 | $2,000 中获准 $1,500；目标本身未改写 |
| 13:20 | 确认模拟成交 $1,000 | 此部分可以进入持仓/账本；不证明整个计划完成 |
| 14:50 | 原取消请求 CXL-007-01 已发出，结果未知 | 不等于取消成功；不释放预留 |
| 15:00 | 最近已确认核对快照 | 确认已知持仓、现金和预留；未知项仍单列 |

没有历史事件时显示“未记录/无法确认”，不靠事件排序或默认时间补造。即使目标生效和计划建立时间相同，也显示两个独立事件。核对动作的进行/结束记录不是新的交易事件，也不是资源释放事件。

## 5. 桌面与移动端信息重排

沿用 NEXUS 深海军蓝底、低反射表面、冷白文字、细分隔线、小圆角，以及现有字体和导航。颜色只作辅助：蓝色定位当前路径，薄荷绿表示已核实事实，金色提醒，珊瑚红标识风险/阻断；所有状态有文本，不新增另一套视觉语言。

| 区域 | 桌面优先 | 窄屏/移动端 |
| --- | --- | --- |
| 导航和上下文 | 保持既有一级导航；紧凑页头 | 使用既有响应式导航容器，保持相同项目、顺序与路由；不增加底部交易快捷栏 |
| 阻断结论 | 位于表格和取舍之前，显示全部关键原因 | 保持首屏优先；不可折叠或被固定按钮遮挡；ID 可换行但不隐藏类型 |
| decisions 取舍 | 短段落后进入目标对照表 | 保持在对照前；默认显示取舍结论和依赖，证据可展开 |
| decisions 对照 | 证券行、V7/PROP-008/实际列并排；数值右对齐 | 重排为按证券分组的只读行卡；每卡重复 V7、PROP-008 未生效、实际及各自时点标签；现金单列完整卡，不压成无标题数字 |
| paper 主区域 | 时间线与核对面板双栏；表格通栏 | 顶部结论后先放原取消核对面板，再放时间线与核对表；保留事件时间顺序，不倒置为“最近成功” |
| 金额/持仓核对 | 稳定数字列，关联来源可展开 | 按对象分组展示需求、获准、成交、未结、缩减；不可把多个维度合成一个进度条 |
| 现金 | 目标现金、实际现金、预留、可用并列且注明关系 | 同一卡内纵排四项；持续显示“实际包含预留”，不能将实际与预留相加 |
| 次要细节 | 证据、历史依据可折叠 | 同样可折叠；关键阻断、有效性、未知、来源异常不可默认隐藏 |

断点沿用现有系统；以内容不截断为准，不在本文发明设备阈值。极宽历史明细可以局部横向滚动并显示提示，页面主体不横向溢出；核心对照必须有可读的窄屏重排，不能仅缩小字号。

读屏顺序与视觉顺序一致；表格保留列标题语义；键盘可展开、跟随链接和发起核对，焦点明确。触控操作采用至少 44×44 CSS 像素的目标区域；缩放后不截断金额、对象类型或风险文案。异步反馈就地提示，不抢走焦点，不仅用颜色/Toast 告知未知。禁用原因始终可见，不能仅依赖悬浮提示。

## 6. 状态矩阵

### 6.1 分维度状态，不合并为一个总状态

| 维度 | 必须区分的状态 | 展示与约束 |
| --- | --- | --- |
| 目标 | 尚未建立 / 生效 / 已被替代 | 只有一个生效目标；历史版本只读，不回写 |
| 本轮判断 | 提议变更 / 维持 / 主动保留现金 / 证据不足 / 政策未确认 | 主动现金是选择；证据不足是缺口；均不能仅写“观望” |
| 提案 | 未生效 / 等待重新校验 / 校验未通过 / 已形成生效目标 / 已过期 | 未生效不得使用 V8 标识；过期不抹掉成交，也不自动执行旧配置 |
| 准入与风控 | 通过 / 缩减 / 拒绝 / 输入不足 | 记录对应对象和原因；不把输入不足显示成风险拒绝或成功 |
| 计划与执行 | 无须交易 / 等待前序结清 / 等待条件 / 执行中 / 部分完成 / 已完成 / 确认取消 / 受阻 / 结果未知 | 是必要业务含义，复用既有状态，不要求逐项新增枚举；“等待前序”可属于提案上下文，不能据此创建第二个占用计划 |
| 资源 | 明确占用 / 已结清或释放 / 尚未查明 | 由订单、预留、账本及核对事实确定，不由计划按钮推定 |
| 研究有效性 | 有效 / 到期待复核 / 证据不足 / 观点失效 | 继承不续期；到期不自动清仓；观点失效仍按合法流程改变目标 |
| 页面读取 | 加载中 / 最新已知 / 数据陈旧 / 读取失败 / 无权限 / 无记录 | 不覆盖业务状态；读取失败不是交易失败；空值不是零 |

### 6.2 关键组合场景

| 场景 | decisions | paper 与资源 | 可推进条件/动作 |
| --- | --- | --- | --- |
| 首次目标建立 | 无上一版本；显示明确初始目标来源及政策依据 | 尚无成交时显示“首次组合启动”，已存在持仓照实保留，不自动复制成目标 | 参数或来源缺失则阻断；不重置账户，不强迫首笔成交 |
| 日常无变化 | V7 继续生效；原判断维持，不累加权重、不制造新版本 | 若适用政策判定无须交易则无须交易；如有实际偏差，由确定性规则检查已有订单覆盖后决定 | 不把“无新判断”直接等同“无交易需要” |
| 部分完成 | V7 仍生效；PROP-008 未生效 | PLAN-007 已成交部分计入实际，未结与缩减分列，占用继续存在 | 已成交不撤回；不使用未成交卖出所得；不另起占用计划 |
| 原取消结果未知（基线） | 明确阻断替换；保留提案供后续复核 | 原请求未知，最近已知预留 $500；实际 $4,000 / 可用 $3,500 带快照时点 | 只允许核对原请求结果，不盲目重发交易 |
| 取消确认但预留仍在 | 仍不放行提案 | “取消已确认；资源未结清”，不能宣称计划全部闭环 | 继续既有对账/收尾；不能仅因取消成功创建新计划 |
| 原请求未取消成功或订单仍在执行 | V7 保持；等待前序结清 | 显示原请求真实结果、订单状态和占用，不自动再取消 | 有限核对不替代后续既有授权处理 |
| 旧计划结清且无未知 | 提案“等待重新校验”，不是立即生效 | 资源及订单/实际一致的证据就绪 | 按最新状态重校验；通过且有合法变更才产生 V8，失败保留 V7 |
| 风控缩减/拒绝 | Agent 原判断与目标不改写 | 获准、缩减、拒绝及原因独立显示 | 不为达到目标而降低硬风控；缩减量不自动成为补单 |
| 证据不足/政策未确认 | 说明具体缺口，不显示配置默认值 | 不生成依赖缺失输入的执行动作 | 保留已有目标；现有风险与收尾处理不被新提案阻塞 |
| 主动保留现金 | 展示现金意图及确定性目标现金 | 现金实际值与资源占用仍独立核对 | 现金合法，无须填满仓位；不把执行滞留现金当主动选择 |

| --- | --- | --- |
| 原始取舍、研究范围、支持与反方证据、角色、失效条件 | 持久化 Agent 研究/判断记录 | 判断标识、证据时点；不允许前端补造理由，不输出权重/数量 |
| 政策依据、配置规则、授权边界 | 已确认且适用的政策及既有生效硬约束 | 显示当时适用版本；未知写“政策未确认”，不以现有参数存在推定获批 |
| 继承标的、继承权重与研究有效期 | 确定性继承结果 + 原生效目标 + 原研究记录 | 原目标可追溯；继承不更新研究有效期 |
| 提案完整权重/金额/现金 | 确定性配置结果 | 关联 PROP-008、政策、估值依据；NVDA 20% 明示确定性来源 |
| V7 内容、生效时间、被替代关系 | 持久化不可变目标及生效事实 | 生效事实缺失不得推定；V7 与提案记录分离 |
| 目标金额 | 目标中固化的金额，或明确标注的基准折算 | 区分当时配置基准与当前估值折算，不以新行情回写历史目标 |
| 准入与风险结果、缩减金额与原因 | 确定性准入/风控记录 | 目标/提案/计划归属及时点；不覆盖 Agent 判断 |
| 计划建立时间、目标归属、调整范围 | 调整计划事实 | 不与目标生效事件混用；无计划则显示无计划，不造占位占用对象 |
| 已成交、数量、金额、费用 | 既有内部模拟成交与账本 | 原订单/计划/目标关联，不能从订单已提交推定成交 |
| 未结订单与预留 | 订单生命周期、预留及结算/核对事实 | 取消请求发出不是释放；未知显示最近已知值与未知范围 |
| 实际持仓与现金 | 既有模拟成交/账本形成的已确认实际快照 | 来源、币种、as-of；不是目标，也不是券商真实账户 |
| 可用现金 | 已核实现金及所有适用占用/限制后的确定性结果 | 本演示为 4000−500=3500；真实场景有其他限制时不可仅作前端减法 |
| 可执行差额 | 目标、实际、已成交、未结覆盖、预留及硬风控的确定性计算 | 目标差额不等于可执行数量；不能由前端或 Agent 临时计算报单 |
| 取消请求结果 | 原请求标识绑定的内部模拟执行/核对事实 | 锁定 CXL-007-01 与 ORD-007-01；缺回报即未知，不按超时判取消成功 |
| 绩效与结果链接 | 既有绩效与账本读取能力 | 同一组合、计划/决策与可比窗口；数据未就绪则注明，不伪造收益 |

所有快照保留币种、单位、分母、来源和实际可用时点。事件发生时间、记录时间、最近核对时间分别命名；不同时间/分母不能直接相减，须显示不可比原因。零、未知、缺失和不适用四者分开。跨币种不静默汇总；有费用、价格变化时分别解释差额，不套用演示恒等式。

## 8. 按钮行为合同

### 8.1 允许的最小操作集合

| 按钮/入口 | 可用条件与目标 | 行为及完成反馈 | 明确禁止 |
| --- | --- | --- | --- |
| 查看调整计划 | 已有可追溯计划；否则显示无关联计划及原因 | 打开现有 paper 对应 PLAN-007，保留组合/目标关联 | 不建立计划、不选择最新计划冒充原计划 |
| 返回组合决策 | 存在原决策关联 | 回到原 decisions 详情及原目标上下文 | 不重新研究、不将原订单归属新提案 |
| 查看目标/实际详情 | workspace、portfolio 的最小摘要入口 | 进入现有 decisions/paper 对应详情 | 不新增驾驶舱、页面或编辑能力 |
| 展开证据/来源/历史 | 存在相应记录；缺失则就地说明 | 只读展开，保留原时点与版本 | 不触发模型、行情采集或有效期刷新 |
| 刷新已存记录（如既有页面保留） | 当前读取权限有效 | 只重读已持久化事实，显示读取时间与业务 as-of；失败保留旧数据并标陈旧 | 不采集券商数据、不运行策略、不重发原操作 |

本精修基线不增加“立即生效”“批准执行”“重试交易”“一键建仓”等按钮，也不新增人工审批流程。目标形成和正常内部模拟运行仍按既有授权与确定性链路进行，不以新增审批按钮接入。既有取消处理能力不因本文被删除，但本核对按钮绝不替代或触发取消动作。

### 8.2 “核对原操作结果”面板的严格边界

面板始终显示：操作类型“取消请求”、原请求 CXL-007-01、原订单 ORD-007-01、计划 PLAN-007、目标 V7、请求发生时间、最近核对时间、当前已知结果与预留状态。

固定解释文案：“仅核对原取消请求结果；不重发买入、卖出、取消或改单操作。”首次点击也不是发起取消，重复点击只核对同一原请求；可以按既有能力幂等更新核对记录和已证实事实，但不能产生新的交易操作。

| 交互状态 | 按钮/反馈 | 业务后果 |
| --- | --- | --- |
| 可核对 | “核对原操作结果”，明确绑定原请求 | 点击只启动有界的幂等核对，不批量扫描并操作其他请求 |
| 核对中 | “正在核对原取消请求…”，本操作禁止重复触发；页面仍可阅读 | 无乐观成功、无乐观释放、无自动重试交易；显示最近已知事实 |
| 已查明取消成功 | 展示取消确认时间；另列订单和预留结清状态 | 取消成功本身不放行 PROP-008；须满足全部结清与重校验条件 |
| 已查明取消未成功/已成交等 | 逐项展示权威原结果与已确认成交 | 不自动重发撤单，不抹除成交，不把核对成功写成取消成功 |
| 仍未知或核对超时 | “尚未查明原取消结果”，保持原占用/未知警示 | 超时不是取消失败；不释放资金、不替换目标；可再次显式核对同一请求，无无限自动轮询 |
| 读取失败/无权限/能力未接通 | 显示安全错误说明与最后已知时点；缺能力时禁用并解释 | 不假装完成，不提供绕过风控或改用交易重试的快捷入口 |
| 关联缺失或记录冲突 | 禁用；说明缺哪个原始关联 | 不猜测最新请求、不用相似订单替代 |

切换组合、目标或请求后，迟到的核对响应不得覆盖新选择；其事实仅归属原对象。刷新和返回页面不重放核对或交易。核对按钮本身不连带启动提案重新校验、目标生效或后续执行；这些必须由既有合法链路独立满足条件并记录。

## 9. 最小用户旅程与设计验收

用户由现有研究入口或 decisions 进入组合决策详情 → 先读是否受阻及当前权威目标 → 读本轮取舍 → 对照完整提案、继承持仓与现金 → 查看准入/配置来源 → 满足条件时由确定性链路形成生效目标 → 需要交易时关联既有内部模拟计划 → 在 paper 查看独立事件、风险与成交 → 核对金额、实际持仓、现金和未知事项 → 前序结清后新提案重新校验。

主旅程的等待分支允许继续研究和形成提案，但不允许双重占用。无交易分支保留有效目标及具体原因；它不是强迫成交的入口，也不能替代自然成交链路验收。

最少界面范围：两个主页面的局部精修（decisions 详情、paper 主区域），两个摘要补充（workspace、portfolio），decisions 列表必要状态/详情关联；market、一级导航不改。所有上述状态复用这些区域，不为每个状态新建页面。

交付验收清单（未来实现须逐项用实际证据验证）：

- 当前 V7、未生效 PROP-008、PLAN-007、原订单/取消请求不会混淆；无提前存在的 V8。
- 生效目标/提案/风控结果/实际四层可同时区分；原始 Agent 判断没有金额、权重和订单数量。
- NVDA 20% 标注确定性配置；继承明确“不更新研究有效期”；遗漏不退出、重复观点不加仓。
- 目标生效与计划建立是两个独立事件；计划建立不代表占用或成交。
- 已确认实际现金 $4,000 包含预留 $500，可用 $3,500；未知期间有快照时点和未知范围。
- 金额拆分守恒；未结订单不重复生成需求；风控缩减不回写目标；卖出未成交资金不可用。
- 首次目标建立、日常无变化、部分完成、结果未知及取消确认但未释放场景均能正确表达。
- 原取消核对重复触发不产生任何交易操作；超时、无权限、缺关联、迟到响应不会释放资源或错误覆盖状态。
- 旧计划完成/确认取消、占用结清、核对一致、无未知后仍须重新校验；没有自动启用等待期间旧配置。
- 桌面/移动端状态与数值一致；核心标签、来源、未知和禁用原因可见；键盘与读屏可达。
- 复用账户、历史记录及链路；不修改真实账户只读边界，不解除 execution_locked=true。
- 受控分支测试与自然真实证据链验收分别记录；概念图、文档、测试数量或仅不交易结果均不等于自然成交闭环完成。
