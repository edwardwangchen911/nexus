## 本次采纳的产品差异

允许用户对指定、已终结且清理确认的独立 `research_and_monitor v3` 请求，显式接受仍未知的历史研究影响。接受仅解除该精确请求对后续调度的历史占用，保留原 unknown、未知用量、未知费用、预算预留、输出和审计。后续研究仍须通过全部原准入条件。

此前计划明确“不新增 v3 未知接受”，原拒绝符合此前合同。这是新增能力，不是放宽一个失败断言。采纳本合同只授权研发、隔离验证和满足既定 CI/回滚条件后的交付；不接受当前真实请求，不授权新模型调用、恢复宿主或重放通知。

## 适用范围与效果

- 仅 `contract_version=3`、`mode=research_and_monitor`、`cycle_id=None`，已经进入实际研究并终结为 unknown；执行成员须有受支持的正式 0099 / research-stages-v1 路由。
- 必须检查完整 manifest 的全部成员，数量沿原合同。支持成功、失败未知和原生未调用取消的混合结果；不能只挑失败的两股处置。
- v2、legacy、准备阶段 unknown、正式周期及未知未来版本仍走原合同或拒绝；不补造身份、route、阶段事实或 cycle。
- 成功成员原合格监控计划可以保留；失败成员不产生计划。计划存在本身不算在途执行。派生增量自身的 unknown、在途作业和未消费有效租约仍独立阻断，不被根请求接受覆盖。
- 未接受时保持原拒绝。接受不结算或释放预算；预算不足、时效、价格、风控、审计否决和 watch 只能 defer 继续独立生效。

## 正式入口与证据

只增加一套正式 CLI check / accept；API、BFF 和页面只读展示处置状态，正常新请求 API 继续走统一准入。

check 不写业务事实、不结案、不 reclaim、不调用模型或来源。其“检查时具备接受条件”不是接受，也不是账户就绪。

accept 要求明确指定请求、操作者和其确认的证明摘要。执行时重新核查身份、完整成员、阶段终态、清理及预算，在受控事务中只追加一次接受审计。证据变化则拒绝，不扩大到新事实。必须将“目标未知请求可否接受”和“账户整体可否继续工作”分开，避免要求目标先通过普通准入形成循环。

稳定证明绑定请求事件链、manifest、完整成员、run/job/route/scope/version、attempt、消费 lease/fence、原截止、阶段授权/观察/核验/cleanup/terminal、输出事件及每成员预算/定价/可信用量下界。原错误正文缺失不需要重放补齐。

接受适用性另绑定接受时原对象全部相关事实的成员集合及缺失项，不能只复用冻结 terminal hash。接受后同一原身份的迟到相关事实（包括同时间戳新增行）使例外失效；原审计与财务不改，旧执行权不恢复。首版不支持对变更后的事实再次接受。无关新请求、新审计、合格计划的正常后续检查和新宿主管理代次不使旧证明失效。

## 并发、消费者与回滚

复用既有生命周期、账户、scope→Job/Lease→budget 锁序及审计链顺序，多个 scope 稳定排序。身份复核、重复检查和审计追加在同一受控事务内；当前安全条件维持至提交。不受现有边界约束的相关写者存在时拒绝，不能仅凭事务前空队列或 PID 快照放行。

并发接受只产生一个语义接受事实；重复读回不停止后续合法工作。COMMIT 确认丢失沿同一身份读取，未决事务下“查不到”不等于已回滚，不自动重发接受。

手动历史准入、独立成员 settled 检查、自然调度历史分支、宿主只读恢复及锁后激活、单股/混合增量准入统一消费同一 reader。例外只覆盖审计指明的未知成员，其他全部门禁仍检查。旧 read / finish 保持 unknown 和幂等；旧 dispatch 永久拒绝。

页面同时展示原 unknown、未知预算和“仅历史调度占用已接受”，不显示为研究合格、已结算或可交易。执行锁始终为 true。

不增加第二套研究执行协议。优先复用 AuditEvent 与阶段证明；交付须有识别新审计、保留旧执行封锁的维护回滚镜像。不能识别的版本必须保持维护拒绝，不能恢复业务。

复用已通过且合同未变的阶段安全等价证据。新增有限回归覆盖：身份范围与错绑定；未知/成功/取消混合；已知前缀及零边界；同日/跨日；无接受仍拒绝；摘要变化、清理缺失、活进程及未消费有效租约；并发和真正 COMMIT 已提交/回滚丢确认；迟到及同时间戳新增；正常新身份不会让旧证明自我失效；全部准入消费者；预算仍不足；原监控计划和一次通知不变；正常 CLI/API/BFF 与桌面/手机实际页面；最终 F/R/F 兼容。
