# NEXUS 产品体验重组设计

日期：2026-09-15

状态：阶段 1 已实现（本地只读验收：2026-09-15）

范围：信息架构、核心流程、页面合同与分阶段交付；不改变交易授权、安全策略或数据事实

## 1. 产品定位

NEXUS 是个人 Agent 股票决策与交易工作台：Agent 在已配置的运行时段内观察市场、形成可解释决策，经确定性风控进入内部模拟，并用交易结果验证决策质量。当前以内部模拟为主，真实账户只读，实盘执行保持锁定。

产品的主流程是：

```text
运行状态 → 查看决策 → 跟踪执行 → 复盘结果
```

研究、行情、数据源、风险审计和策略实验为这条流程提供证据或配置，不再各自占据同等权重的一级入口。

## 2. 设计原则

1. 用户首先看到当前模式、系统是否真实在线、最新决策和需要处理的事项。
2. “最近有持久化结果”与“循环进程在线”是两个独立事实，不能互相推断。
3. 页面默认只读取已持久化事实；刷新页面不触发行情采集、模型调用、运行重放或订单动作。
4. 内部模拟与真实只读账户始终分开展示，不合并估值，不暗示真实账户可执行。
5. 无订单可以是正确结果；数据不足、模型失败、风控拒绝、无须调整必须分别表达。
6. 结果未知时先核对原操作结果，不提供直接重试交易。
7. 先展示决定和影响，再逐层展开证据、计算、审计与底层代码。
8. 保留现有暗色、克制、专业的视觉语言，优先通过层级、间距、分组和分隔线组织内容，不堆叠卡片。

## 3. 信息架构

### 3.1 一级导航

| 入口 | 用户问题 | 核心内容 |
| --- | --- | --- |
| 交易工作台 | 今天系统在做什么，我需要处理什么？ | 运行状态、最新决策、活动订单、异常、今日摘要 |
| 决策记录 | Agent 为什么买、卖、持有、观察或停止？ | 决策列表、证据链、仓位计算、风控和执行关联 |
| 账户与交易 | 钱、仓位和订单怎样变化？ | 内部模拟和真实只读账户、持仓、订单、成交、资金流水 |
| 复盘 | 决策执行后的表现如何？ | 绩效、成本、归因、基准对照和次级策略实验 |
| 设置与运行 | 系统如何配置、运行和排障？ | 数据源、Bark、服务状态、运行范围和风险限制 |

“设置与运行”在视觉上属于次级导航。全局持续显示“内部模拟”和“实盘锁定”，不依赖进入特定页面才能确认安全边界。

### 3.2 现有页面迁移

| 现有入口 | 新归属 | 迁移策略 |
| --- | --- | --- |
| `/overview` | 交易工作台 | 将风险摘要、数据新鲜度和需要补充的证据并入首页 |
| `/paper` | 交易工作台、账户与交易、复盘 | 作为新首页的主要事实基础，拆分而非复制 |
| `/portfolio` | 账户与交易 | 保留真实只读账户，优化币种和诊断层级 |
| `/market` | 决策详情、次级工具 | 从决策证据或标的链接进入 |
| `/research/[instrumentId]` | 决策详情 | 作为研究证据层，不作为一级入口 |
| `/optimize`、`/what-if` | 复盘／实验 | 保留历史读取和试算能力，降低导航权重 |
| `/strategies` | 复盘／实验、设置与运行 | 表现与版本历史进入复盘；运行控制进入设置 |
| `/risk-audit` | 决策详情、设置与运行 | 单次事件随决策查看；系统级审计作为次级工具 |
| `/integrations` | 设置与运行 | 汇总数据源、模型、Bark 和服务状态 |
| `/broker-simulation` | 设置与运行／实验 | 保留为执行联调工具，不进入日常主流程 |
| `/live-approvals` | 暂时隐藏 | 能力未实现前不显示批准入口 |

第一阶段保留旧路由和直接链接，不删除底层模块、历史记录或 API。新导航稳定后再决定是否增加兼容跳转。

## 4. 核心用户流程

### 4.1 日常查看

1. 用户进入交易工作台。
2. 顶部确认当前为内部模拟、实盘锁定，并分别查看循环在线状态和最近持久化周期。
3. 查看最新决策及一句话原因。
4. 若存在待处理事项，查看影响范围和安全动作。
5. 进入决策详情核对证据、风控和执行链。
6. 需要时进入账户与交易或复盘查看后续结果。

### 4.2 异常核对

1. 首页将数据不足、模型失败、风控拒绝、订单结果未知和服务离线分开显示。
2. 每项异常说明受影响的周期、决策或订单。
3. 页面只提供读取或核对动作，例如“查看缺失证据”“核对原操作结果”。
4. 任何结果未知状态都锁定相关后续写入，不提供直接重放。

### 4.3 未来运行控制

第一阶段只显示状态和本机运行指引。未来增加写操作前，必须由独立后端合同支持：

- 运行一次；
- 开始连续运行；
- 停止产生新决策；
- 已有订单继续处理、保持或取消的独立策略。

停止新决策不等于取消已有订单，关闭页面也不等于停止循环。

## 5. 页面设计

### 5.1 交易工作台

采用“决策优先”布局：

```text
┌ 当前模式 ─ 实盘锁定 ─ 循环状态 ─ 最近周期 ─ 下一时段 ┐
├ 最新决策与原因 ───────────────────┬ 需要处理          │
│ 决定、核心原因、失效条件、时间       │ 异常与安全动作      │
│ 查看完整决策                        │ 无事项时明确显示正常  │
├ 活动订单与执行状态 ────────────────┴───────────────────┤
├ 最近运行周期 ─────────────────────┬ 内部模拟账户摘要     │
└───────────────────────────────────┴────────────────────┘
```

首屏不展示完整诊断账簿、长持仓表、完整归因表或全部策略指标。数据源过期时保留事实，但必须在相关结论附近显示影响。

### 5.2 决策记录列表

默认按运行周期倒序展示：

```text
时间｜标的或候选范围｜Agent 决定｜风控｜订单／成交｜最终状态
```

支持按日期、决定类型和最终状态筛选。第一阶段不增加任意全文搜索。列表行必须能够区分无订单、数据不足、风控拒绝、部分成交和结果未知。

### 5.3 决策详情

采用“运行时间线”布局：

```text
运行窗口
  → 市场与研究证据
  → Agent 决策
  → 确定性仓位计算
  → 确定性风控
  → 订单或无订单结论
  → 成交、取消、对账或结果未知
  → 后续表现
```

详情首屏展示决定、核心原因、决策时间、证据截止时间、失效条件、是否产生订单及是否需要处理。完整证据、原始状态码、计算输入和审计事件默认折叠。

### 5.4 账户与交易

顶部明确切换“内部模拟账户”和“真实只读账户”。

内部模拟账户展示净资产、现金、预留资金、持仓、活动订单、历史订单、成交、费用和资金流水。真实只读账户按原币种呈现，零资产币种默认折叠；持仓事实与研究完整度分列，不在每个持仓中重复展开整份研究缺口。

### 5.5 复盘

复盘首页采用结果闭环结构，但只有在相同起点、相同观察窗和数据完整性可比时才展示 Agent、保持不动、`baseline_v1` 和市场基准。未具备的年化收益、胜率、成本或归因保持未知，不用示例数字填充。

优化、Proposal Shadow、策略进化和回测进入“策略实验”次级区域。实验结果不会自动改变当前运行策略或交易权限。

### 5.6 设置与运行

分为运行状态、数据源与服务、通知、模型、风险边界五组。凭据只显示已配置或未配置，不回显值。硬风控修改、策略晋级控制和 Agent 循环控制保持独立，不合并为一个总开关。

## 6. 统一状态模型

| 层级 | 状态 |
| --- | --- |
| 运行 | 尚未开始、等待时段、运行中、最近周期完成、已停止、非运行时段、日历不可用、进程状态未知 |
| Agent 决策 | 买入、卖出、持有、观察、数据不足、模型失败 |
| 仓位与风控 | 无须调整、输入不足、风控通过、风控拒绝 |
| 执行 | 无须创建订单、等待行情、已提交、部分成交、已成交、已取消、已拒绝、对账中、结果未知 |
| 数据质量 | 就绪、部分缺失、已过期、不可用 |
| 用户处理 | 无需处理、建议查看、必须核对、等待外部条件 |

状态显示由稳定的后端事实映射生成，不从文案、页面是否打开或单一 HTTP 状态推断。

## 7. 数据与接口设计边界

第一阶段优先增加只读投影，不建立新的 Agent 框架或第二套账簿：

1. 工作台聚合投影：运行摘要、最新决策、活动订单、待处理事项和账户摘要。
2. 进程状态投影：循环 heartbeat 与最近持久化周期分别返回。
3. 决策列表与详情投影：使用稳定 ID 关联周期、决策、仓位、风控、订单、成交和绩效。
4. 待处理事项投影：返回问题类型、影响范围、安全动作和关联对象。
5. 复盘投影：只返回同窗可比且有完整性说明的结果。

Bark 当前固定摘要保持不变。完整通知需要以后新增脱敏通知投影，不能直接透传 outbox payload、账户事实或底层错误。

## 8. 页面状态与可访问性

每个核心页面必须覆盖：加载、空数据、就绪、部分缺失、已过期、失败和无权访问。订单链另外覆盖等待行情、部分成交、对账中和结果未知。

- 状态不能只靠颜色表达，图标、标题和说明必须同时存在。
- 页面跳转后焦点进入主要内容；移动导航跳转后自动关闭。
- 可横向滚动区域必须可键盘聚焦并有明确标签。
- 展开控件、导航和状态筛选必须具有可访问名称。
- 动态读取状态通过有界的 `aria-live` 区域通知，不重复播报整页。
- 截图只能发现可见风险；键盘顺序、读屏语义、缩放和焦点恢复仍需浏览器专项验收。

## 9. 分阶段实施

### 阶段 1：建立主体验

- 新导航；
- 只读交易工作台；
- 决策记录列表和详情；
- 旧入口迁入次级位置；
- 移动导航关闭和可访问名称修复；
- 所有核心读取状态。

不加入页面运行控制、人工批准、硬风控编辑、Bark 完整摘要或实盘能力。

### 阶段 2：账户与订单体验

- 内部模拟与真实只读账户重新分组；
- 活动订单、订单详情、成交和资金流水；
- 部分成交、取消、对账中和结果未知流程。

### 阶段 3：复盘与通知

- 同窗绩效、成本和归因；
- 策略实验次级区域；
- 经脱敏设计的 Bark 决策与执行摘要。

### 阶段 4：运行控制

只有在独立控制 API、幂等、并发、审计、停止语义和恢复流程完成后，才增加运行一次、连续运行和停止新决策。

## 10. 阶段 1 验收标准

1. 用户在首页能判断当前模式、循环是否在线、最近周期状态、最新决定和是否需要处理。
2. 从最新决策一次点击进入完整证据链。
3. 无须调整、数据不足、模型失败、风控拒绝、部分成交和结果未知具有不同表达。
4. 页面刷新不触发行情、模型、运行重放或订单写入。
5. 真实只读和内部模拟在导航、标题、账户和订单层始终可辨认。
6. 不展示没有可靠事实支持的收益、订单、实时状态或运行能力。
7. 移动导航跳转后关闭，键盘焦点进入主内容，主要控件具有可访问名称。
8. 旧路由和历史读取继续工作；不删除模块、迁移或历史数据。

## 11. 明确不做

- 不重新设计交易、风控、账本或研究引擎；
- 不新增前端框架、图标库或视觉依赖；
- 不把页面在线当作循环在线；
- 不从浏览器启动数据采集或模型调用；
- 不开放模拟或实盘写入；
- 不提前显示未来审批控件；
- 不为设计效果制造收益、成交或实时数据；
- 不删除旧页面、底层模块或历史数据。

## 12. 回滚与兼容

阶段 1 以新增只读页面和调整导航为主。旧页面和 API 保持可直接访问；若新工作台验收失败，可恢复旧导航而不迁移或回写业务数据。任何接口扩展优先新增只读响应或兼容字段，不改变已有订单、风控和审计语义。

## 13. 阶段 1 本地验收证据

2026-09-15 使用当前 worktree Web、当前 Engine 只读投影和既有 `nexus-fosun-live` 持久化数据完成验收；
使用隔离端口，不重启主检出目录已有服务，不启动 worker、Provider、模型或 Agent 周期。

| 验收项 | 脱敏结果 |
| --- | --- |
| 模式与权限 | `internal_paper`；`execution_locked=true` |
| 循环与周期分离 | heartbeat 缺失时显示“循环状态未知”；已保存会话独立显示“已完成” |
| 最新周期 | `01a0a54e…`；决策时间 `2026-09-15 21:43:23 北京时间` |
| 决策详情一致性 | 工作台一次点击进入同一 `01a0a54e…`；决策 `01a0a550…`；报价时间 `2026-09-15 21:43:22 北京时间` |
| 订单状态 | 活动订单为空；周期结果为 `NO_ORDER_REQUIRED`，页面显示“无需下单”，不再显示“处理中” |
| 未具备事实 | 风控结论和统一后续表现保持“未知”，没有从其他周期补填 |
| 浏览器请求 | 只观察到工作台、集成和精确周期的 GET；没有业务 POST、PUT、PATCH 或 DELETE |
| 浏览器运行 | 当前页面控制台无 error 或 warning；旧路由仍由聚焦浏览器回归覆盖 |

该记录验收的是当前真实持久化 no-order 读取路径，不代表真实 Agent 自然订单、部分成交或长期绩效已经
完成运行验收，也不解除实盘锁。阶段 2–4 仍按本设计的独立范围推进。
