# API 资格轮登记与只读核对

## Sol 正常业务价档（0113；独立于历史资格轮）

正式日研究、独立研究和受影响股票的增量研究默认使用直接 Platform API 的 Responses 路线，
模型为 `gpt-6.1-sol`，推理档位为 `medium`。运维可显式切回 SDK。回切只适用于按原共享预算和
门禁准入的新任务。已发送的 API 请求仍按原身份核对，结果或费用未知时保留原预留。
[业务路线决策](../design/nexus-direct-responses-evaluation-v0.1.md)

`nexus-platform-local register-sol-profile --price-record /absolute/price.json
--source-evidence /absolute/source-evidence` 登记已核验的 Sol 价档与请求配置，
`nexus-platform-local inspect-sol-profile --model-config-id UUID` 只读回原记录。
在正常运行根目录执行；两份输入均为本机私有文件（0600），不包含 Key、账户或资金材料。
命令使用项目正常配置连接本机数据库，不读取模型凭据、不访问 provider、不启动宿主、
不创建研究或预留预算，也不改变当前默认路线。

schema 0118 增加显式 `--output-format compact-v3`：在三阶段任务指令中追加紧凑 JSON
生成指导，模型、推理档、价格、8192 输出上限和原接受规则不变。默认仍为 `structured-v2`。
格式选择进入既有不可变模型档案及其哈希；同一价档登记新格式会得到不同的配置编号，
不是覆盖旧档案。正常排队请求和盘中意图已绑定原配置，旧请求仍按原格式准备；
不能修改旧请求绑定或绕过配置一致性检查来切换格式。注册本身不切换宿主，
后续配置选择仍走原维护部署流程并核对没有活动或待处理工作。紧凑档案续核也须显式指定格式。

独立三股的压缩输入仅展开任务指令字段再追加指导，原证据、字符串表和前驱内容保持；
实际展开后的完整请求重新计入容量，超限仍拒绝。已有 v3 档案时禁止降回0117，
回滚使用保留0118读取、结案和未知保护能力的维护镜像，不删除新档案或改写旧结果。
0118降级在首次判空前对模型档案表取得事务写入围栏；存在未结束写事务时立即安全拒绝，
持锁期间正常登记不能穿过检查窗口。已有compact-v3档案继续禁止降级，不以维护状态代替此保护。

价档遵循 `platform-sol-pricing-v1`：准确模型 `gpt-6.1-sol`、标准 tier、implicit 30m、
USD、官方标准价表 URL、实际归档原件的 SHA-256、核验与失效时刻，以及普通输入、
缓存读、30m 写、完整输出的四项每百万 token 单价。单价为十进制字符串，最多六位小数；
不得从请求参数补齐响应中的实际模型、tier 或用量分类。来源摘要相符只是归档身份核对，
运维仍须先核对真实官方原件，登记不等于实时账单或资金来源证明。

本地有效期上限为 168 小时，不按跨夏令时的七个日历日计算，不代表官方锁价。
新研究准备须验证窗口覆盖原有界期限，发送前重验；旧价档过期不阻止历史读回和
按原始用量结案。续核产生新的不可变价格/模型身份，不修改旧记录或增加日期白名单。
SQL 与应用共同核对完整价档、配置 hash、Sol medium 请求格式、容量及保守预留费率；
原 Terra 实验 profile 和权限保持独立。

正常准备在原 formal / independent / increment 所有者事务中冻结实际模型、价档、
凭据指纹、三阶段输入与容量，并与原共享预算预留一起提交；拒绝时不留下部分股票的
Job 或预留。仅登记新价档不改变旧请求路线。旧路线读回不要求当前 Key 或未过期价档；
新的阶段发送仍须匹配其冻结路线与正式阶段授权，不能借 SDK 授权或实验身份发送。
单股接替保留前驱的模型、价档和输出。子任务冻结本次选定的已登记配置。
正常 Worker 复用既有三阶段执行器、HTTP 生命周期和短事务工具；领取前重验整个原候选池，
发送前核对原模型、价档、凭据、输入及容量。阶段授权 v2 绑定这五类原始事实及实际请求体，
SQL 与应用同时拒绝错配；不借历史比较身份发送。预检查仍受原 195 秒外层上限约束，
保留原模型和清理期限，失败或回执未知不重试、不自动转 SDK。

已知费用只按原始实际模型、tier、缓存分类和原冻结价格精确结算；正常与孤儿结案、
终态证明及占用读取使用同一投影，价档过期不改历史费用。分类缺失、授权提交不明、
超限或缺少清理证明继续保留相应未知和预算保护。正常结构化合成沿原审计否决和
watch/defer 语义；旧 Output 不重算。离线 HTTP 替身回归不证明真实 Sol 生成、监控接替、
当前默认配置或 SDK 实际运维回切已通过。

正常宿主的显式 Responses 配置须与 Sol 模型身份一致；配置读回保留原 Key，
不调用 SDK 登录检查，也不改变旧 SDK 路线。启动配置检查不代替数据库冻结身份、
当前价档、预算和派发授权。双并发池继续受原调度器与派发租约约束，不能直接领取
未获派发的成员。领取前固定拒绝仅对已证明未派发的任务正常结案；未知任务和费用
继续占用原保护，未使用的同池任务按原取消合同关闭。

阶段读服务、监控来源和正式输出门禁读取原生阶段事实，不以版本白名单授予资格；
监控来源要求已知用量及清理证明，独立研究不能成为正式组合来源。单股新结果保持
前驱输出不变；是否安装新监控计划仍依原证据和采纳合同。历史 schema 缺少原生配置列
时只读为 NULL；旧终态哈希只规范化新增空字段，不忽略非空原生绑定。
正式周期和单股增量只从原 Worker 的输入检查接受原生前置拒绝。相同错误文字不证明
未外发；必须核对原冻结路线、全池所有权、无既有尝试或输出及原预算，才可按零调用收尾。
原生租约沿用有界时长，不改 Run 或预留的价格版本。有效租约和已未知的用量继续阻断；
增量派发回执已登记而结果不明时只读原身份，不再次执行 Worker。

正式研究的未知结果必须有原 Sol 价档、原生阶段证明、已确认清理、仍为 reserved 的
原付费预留，并经过原封存入口的明确接受和其它占用检查。符合资格或已接受只改变
历史调度占用，不释放预留、不推断费用、不改 Run。活租约不被接管；过期孤儿仍由
原恢复事务结案。SDK 历史零费条件保持，0113 的空模型档案不改变旧审计指纹。
这些离线覆盖不证明已部署的默认选择、公开 API / 实际页面、真实宿主恢复、
SDK 运维回切或自然监控验收。

正常日研宿主选择 Sol 时，在受保护的宿主配置中设定 `AGENT_RUNTIME_MODE=responses`，
将 `OPENAI_EXTRACTION_MODEL` 和 `OPENAI_REASONING_MODEL` 均设为 `gpt-6.1-sol`，
把登记回执的精确 ID 填入 `NEXUS_AGENT_PAPER_FORMAL_MODEL_CONFIG_ID`。
宿主在内存中读取 `nexus-platform-local save-key` 已保存的项目 Key。已有显式 Key
须与文件一致。组织、项目或 API 目的地冲突时，配置读取失败。

Compose 将现有 `AGENT_DAILY_BUDGET_USD` 传给 HTTP API，入队回执沿用宿主额度。HTTP API 使用同一宿主路线生成准入身份，Responses 模式下不加载项目 Key。独立研究请求只登记到宿主领取队列，合格的 Sol 档案沿用受限双并发策略。通用研究入口仍按宿主路线执行价格门禁。通用组合决策可用既有的 `PORTFOLIO_DECISION_RUNTIME_MODE` 单独指定路线，未指定时沿用宿主配置。

启用正式预算保护时，在自然槽前通过 `nexus-engine-formal-budget-protection` 应用
当日配置，并以 `--status` 读回。该日已应用的绑定决定模型 ID、hash 和价档。
改动配置文件后须按原合同重新应用。检查到槽已认领时，保留该槽原来的身份。
Sol 的预算绑定记录有界研究时长，Job 为 300 秒、处理器为 315 秒。

隔离库覆盖了宿主读取配置、派发三项研究、阶段结算和监控登记。受控样本中两项
有合格价格提案，第三项保留审计否决。再次核对时沿用原覆盖回执。
自然日研在三项研究成功后进入组合合成。正常恢复入口验证正式周期身份、原输出、
已知用量及清理、精确登记的 Sol 模型与价档，并沿用原来的时效、价格和审计检查。
合格时创建一个组合 Run、Job 和共享预算预留。重复恢复读回原 Job。
watch 或 partial 来源仍只能产生 defer 选择。

组合 Worker 按原 Job 冻结的模型、三股来源和同一项目凭据选择 Responses。
准备事务绑定正式提示、模型与价档、请求字节指纹和原共享预算。宿主在原有领取及
时限内重新核对来源和预算，只发送一次。普通队列和 SDK 均在领取前核对原模型。
兼容回滚镜像须识别原生 Job 和回执，运维回切仅作用于之后通过准入的新身份。

组合 Job 的审计按顺序记录准备、授权、服务端终态（如已收到）和本地清理。
授权提交不明时停止。终态或清理写入确认丢失时，只读回同一 Job、尝试和请求指纹
下的原记录。匹配后继续结算。响应原件中的模型、服务档位、输入、缓存读写和输出
计数共同确定费用。输出未通过组合校验但费用可核实，仍按实结算。
缺少计费字段、缺少必要回执或清理未确认时保留预留。已确认的本地发送前拒绝
可按零外发收尾。取消和迟到结果继续受原租约和尝试保护。

正常恢复按原租约、尝试、已准入的逐股来源与组合 HTTP 回执结案过期孤儿。
原价档到期后仍可结算已有可靠回执的费用；再次读取沿用原结案记录。
对新研究继续检查当前价档。未知费用及预留继续阻止后续准入。
已知费用在当前有效租约到期后才通过账户占用检查。

隔离库通过正式宿主完成三股九阶段和一笔组合 HTTP 替身请求，原周期按
`PORTFOLIO_ASSESSMENT_DEFERRED` 收尾。已核对缓存计价、审计否决、
重复派发隔离和历史占用保护。真实默认路线、自然触发及部署后的页面另行验收。

登记提交回执未知时返回 `PLATFORM_PROFILE_REGISTRATION_RESULT_UNKNOWN` 和已准备的
配置 ID/hash，后续仅用 `inspect-sol-profile` 核对该 ID；不要换时间、换价档或重新登记。
同一登记的并发调用只产生一份配置和审计。0113 尚无 Sol 记录时可以降回 0112；
已有记录则拒绝降级，必须保留 0113 并使用支持其事实的兼容维护镜像。
维护镜像与 SDK 正常业务回切仍须分别验收；此价档入口本身不证明正常生产者、
Worker、监控接替或 Sol 自然运行已贯通。

以下步骤适用于 schema 0111 及以上的历史 Terra 资格轮，用途为 `platform-qualification-v1`。同一受支持配置下，
后续轮次只登记新的实验 UUID 和冻结预算，不增加用途枚举、迁移或发布版本。
旧用途和旧结果保持原身份、原唯一约束及只读核对能力。

## 登记前

先保存本轮 UUID 和私有输出目录，核对是否已有对应登记或任务。正常运行根目录中的
`.secrets/nexus-platform-local/qualification-rounds/<UUID>/` 是权威冻结包及登记尝试的位置，
随既有本机凭据和私有状态保留；部署、备份和回滚不得丢弃它。`--output` 只是导出目录，
换导出目录不会获得新的冻结或数据库提交资格。目录创建逐级同步父目录项，失败在数据库尝试之前拒绝；已有标记不删除。保留一次已核验的任务政策
原件及其 SHA-256；当前任务无需逐轮请求预算批准。`continuation-evidence` 留存上一轮的
诊断与继续依据，不把失败或未知当成可重试。原未知费用、预留和有效租约继续参与准入。

源文件是正常入口已归档的冻结资料；模板仅复用既有评价协议。实现 SHA 必须来自独立核验
的已部署版本，传入参数本身不是版本核验。配置、价格有效期及模型容量仍须合格。
凭据只经正常本机入口读取，不在命令、聊天或普通日志中输入 Key。

下面变量由本轮已保存的身份和已核验文件提供，不在循环中重新生成 UUID：

```bash
.venv/bin/nexus-engine-research-comparison register-round \
  --repo-root "$NEXUS_REPO_ROOT" \
  --experiment-id "$ROUND_ID" \
  --source "$FROZEN_SOURCE" --source-sha256 "$SOURCE_SHA256" \
  --template "$EVALUATION_TEMPLATE" \
  --task-policy "$TASK_POLICY" --task-policy-sha256 "$POLICY_SHA256" \
  --continuation-evidence "$CONTINUATION_EVIDENCE" \
  --implementation-sha "$VERIFIED_DEPLOYED_SHA" \
  --output "$ROUND_DIRECTORY"
```

登记不调用模型、不预留原生位置预算、不启动宿主。回执
`bound_frozen_positions_unreserved` 仅表示整轮上界已冻结；实际预留、领取和发送仍逐位置走
原 `admit-position`、`run-position` 路径，受共享账本和全部门禁约束。
实验质量按该轮冻结输出和原评分规则核对，正式决策仍须通过独立门禁。

### 显式选择 medium 诊断配置（0112）

历史 Terra 资格轮的默认推理档位为 low。已评审的 medium 单变量诊断须在正常
`register-profile` / `inspect-profile` 上同时指定
`--purpose platform-qualification-v1` 和
`--profile-version platform-terra-medium-implicit30m-20261101-v1`；
`register-round` 也必须显式传入同一个 `--profile-version`。独立 `prepare` 支持相同选择，
但已登记的轮次继续消费原冻结包，不重新 prepare。其他历史 purpose 拒绝该选择。

配置选择固化进权威包；同一 UUID 换 effort、版本或导出目录都不能重新冻结或登记。
使用该配置返回的 model_config_id 准入，不套用旧 low 模型记录。官方支持 medium 不代表
本地质量已合格；三阶段累计 output 仍为 8192 且包含 reasoning，用完即停，不增大上限。
价格截止仍 `2026-11-02T00:00:00Z`，现有旧未知费用与共享预算保护不变。

### 共享额度与本机配置

`AGENT_DAILY_BUDGET_USD` 是正常 `infra/.env.local` 的可配置共享日限额；默认 3 美元
不是不可变的产品政策。按当前任务的费用授权，核对既有实际消耗、所有未知预留、
完整待执行包络、正式未来义务及合理余量后设置有界值；不靠清空旧账或等待日切来解决
已知不足。不修改未获授权的业务预算绑定，不充值或解除交易门禁。
正常 CLI 每次读取该配置；常驻进程和容器须在正常重载/部署后另核对生效，不能仅以文件
更新宣称所有运行消费者已变化。修改前保留私有原件及指纹，回退只恢复本次键值。

Platform 每次 `admit-position` 在既有共享会计/UTC 日锁下检查所有**尚未准入位置**的
冻结最大值。已有位置的预留或实际结算由共享账本计入，不再叠加一次。正式未来义务、
其他消费者和历史未结会计门禁仍生效；成功时只给当前位置建立原生预留，不为未来位置
新建占用，也不保证它们稍后一定可用。并发占用变化后，下一位置必须重新检查。
原费用和会计日期不移动，跨日不补充实验自身冻结总额；未知仍保留在原账本及资金核验中。

整轮容量不足返回 `COMPARISON_ROUND_BUDGET_EXHAUSTED`。原生准入事务确认回滚后，
正常入口在既有审计链追加拒绝回执；`inspect-round.last_admission_refusal` 保留历史原因。
这与已发送失败、已消费位置或永久停止的 scope 不同，不伪造 Run/Job/终结证明。
审计写入或提交回执不明返回 `COMPARISON_REFUSAL_AUDIT_UNCONFIRMED`，只读核对，不自动重试。
确无原生身份/发送、scope 未停且有明确继续授权时，可由正常入口准入尚未消费的位置；
原拒绝回执、已成功结果及冻结 manifest 都保留。已经消费的位置继续拒绝，不能换键重放。

## 阶段合成与历史展示

Platform 价格版本与 SDK 版本分别登记。只有精确模型配置、Run 的模型/价格身份和原生
实验绑定均验证通过，新的最终合成才消费既有三阶段结构化复核；不借用 SDK 版本或
改变费用身份。最终论点、逐项复核及不确定性来自已保存的组合阶段，证据审计非支持时
仍否决“充分”；缺合格价格仍为 partial，watch 不产生执行许可。

历史最终意图保持原样，不补写复核或重算质量。详情页通过相同实验身份与既有内容摘要、
冻结证据、提示及引用检查，只读展示原始三阶段记录；身份或内容不能验证时显示校验失败，
不展示未经验证的论点。原始模型自评与系统最终研究状态分别展示，均不代表独立质量验收
通过，也不解除实验隔离或正式业务门禁。

## 中断和不明结果

本地文件交付中断时只恢复原 UUID 和原参数；冻结时间、预算与输入不得重生成。
持久化登记尝试后，重复登记只读回原身份，不再次插入。提交结果不明时返回非零退出，
保持 `unknown` 和 `replay_allowed=false`；不得删除权威尝试标记或换 UUID 自动重试。
同 UUID 换导出目录只复制原冻结内容并读回原数据库事实。

文件发布在硬链接后发生进程退出时，恢复仅在排他发布锁中移除可精确证明归属的临时别名：
目标名和内容摘要匹配、同 inode、仅两个链接、私有目录及文件权限。恢复保持原 inode 和字节，
不产生新的登记尝试。未知别名、多余链接、内容或权限变化继续拒绝并保留文件；正常读取仍
要求 `nlink==1`。维护镜像拒绝新登记，历史查询继续使用 `inspect-round`。

  --repo-root "$NEXUS_REPO_ROOT" --experiment-id "$ROUND_ID"

## 原首版准备退出的限定历史读取

`28e5ff2fb4770ea415a599c0fa3d3763f1a899bf` 的首版 Platform 入口曾在充分验证准备之前
安装阶段成员，最终可能留下 `skipped / abstained / evidence_authority_missing`、空且未知的
阶段 terminal 与原预算 released 的矛盾组合。公共 terminal reader、旧位置 inspect、同轮后继
位置和重放仍拒绝；不改旧行，不把零字段或 released 当作结算证明。

跨实验互斥另按 `historical_platform_preparation_isolated` 核对完整冻结身份、原生绑定、
唯一 attempt/lease/fence、停止 scope/chain、事件/输出/terminal 哈希及时间关系。限定用途和

旧执行未进入外发且永久不能重领或授权；没有进入 provider 生命周期意味着清理不适用，
不是 `cleanup_confirmed=true`，也不授予模型质量、费用结算或未知接受状态。

无派发的因果依据来自该提交中的实际入口：`comparison_execution.py` 固定选择已绑定
Platform 的 responses 路由；`research_stages/executor.py:276` 先 await 授权，失败或提交不明
直接抛出；`protocol.py:343` 插入精确 run/job/attempt/lease/fence 授权，362 行提交、369 行才
返回 ticket；HTTP client 在 executor 的 368 行才构造，生命周期任务随后才启动。
0099 的 authorization immutable trigger 禁止正常 UPDATE/DELETE，授权 SQL 同时要求原 Job
running、预留有效及 scope 未停止。结合空的完整授权集合，才能推导未进入外发，不能只凭
错误原因、零 token 或当前无活动租约推断。实现 SHA 参数本身也不是运行版本证明：实际案例
须复核原入口/部署及执行记录；此次原正常调用包装在启动前核对了冻结实现提交，并保存退出
回执，私有原件留在本机。该固定兼容边界不用于登记后续新轮的版本白名单。
