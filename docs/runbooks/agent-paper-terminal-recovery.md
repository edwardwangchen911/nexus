# 已失败周期的未领取研究收尾

此入口只取消原 `failed/unavailable` 定时周期中从未领取的研究任务，不重放来源、模型或周期，
不创建决策或订单。须先部署通过验证的版本，并取得本次主库收尾授权。

在主仓库 main 核对同版本宿主/API/Worker、执行锁和原周期持久化状态，然后执行：

```bash
uv run --project engine nexus-engine-manual-paper --repo-root "$PWD" \
  cancel-unused-research --cycle-id <原失败周期ID>
```

账户来自受保护配置，调用者不能指定账户、模型、报价或截止时间。宿主缺失或版本不匹配时拒绝。
入口核对账户归属、执行锁、原周期完整事件链及当前订单/预留，手动请求关联周期仍使用原手动收尾入口。
仅接受原 Run、Job、模型和预算绑定一致、无领取/租约/输出/用量的 queued/prepared 任务。
旧 v4/v5/v6 使用原默认 Job 领取协议；v8 保留专用协议，v7 不进入兼容范围。

取消沿用 native fenced claim/finalize：Job 为 skipped，研究为 abstained，确定零调用的费用/用量为零。
原失败周期及其事件保持不变。返回 `cancelled_research` 只表示本次收尾数，不表示账户全部就绪。
已领取或用量未知的任务不被清零，其他历史阻塞继续保留。相同周期重复调用不新增领取或费用。
整次调用在同一数据库事务中；任何校验或写入失败整体回滚，保留失败证据，不重复调用试探。
取消后的持久化事实不能通过回退应用删除；主库操作前备份，回退代码/服务时保留收尾审计。

## 历史已停止、用量未知研究的显式封存

这是独立的恢复政策。先取得具体历史周期/Run 的主库封存授权；本地实现批准不包含部署或主库操作。
仅接受早于数据库当前 UTC 日期的 v4/v5/v6 或规范冻结的正式 v8/v9、组合综合前失败周期。
隔离候选、经济通道及其他未支持版本仍拒绝，不改变原日期限制。

```bash
uv run --project engine nexus-engine-manual-paper --repo-root "$PWD" \
  seal-failed-research --cycle-id <原失败周期ID> --run-id <已确认停止的RunID> \
  --accept-unknown-usage
```

一个调用可明确列出同一周期的 1–5 个 `--run-id`，不支持全账户自动扫描封存。
封存是停止后的维护操作，不要求派发宿主在线，不启动宿主或 Worker。须使用全新正常 CLI 进程，
从受保护配置解析本机数据库和账户；核对请求仓库 HEAD、已加载 Nexus 源码的实际路径及
与该 HEAD 的逐字节一致性，并在迁移版本表事务锁下核对数据库唯一迁移版本。提交前再核对
代码身份；期间变化时整个恢复事务回滚。缺失、混用其他
checkout、源码改动或 schema 不匹配均拒绝。`start` 和 `cancel-unused-research` 仍要求新鲜同版本宿主。
正常入口重新核对受保护账户、原事件链、Run/Job/模型绑定、内部零预留与零单价、
无收费工具、已结束且不可重试的唯一尝试、过期租约、无综合/执行结果及当前账户投影占用。
宿主及既有 `nexus-fosun-live` 容器只读核对进程身份和执行映射，不读取进程参数、环境或凭据。
开发桌面应用的子进程仅认可直接 `CodexCLI → ChatGPT` 或固定
`CodexCLI → cua_node/node_repl → cua_node/node → CodexCLI → ChatGPT` 父子链。
每个节点须精确匹配应用内绝对路径、当前用户、独立执行映射及唯一绝对非研究工作目录，
整链 PID/PPID/UID/启动时刻/路径与全部 Codex 候选集合须在前后快照中一致。
该检查只证明观察时段的身份与映射，不是持续进程锁；封存时必须重新检查。
投资 SDK、无法确认归属的 Codex 或扫描失败仍拒绝；不会自动停止进程，不用租约过期代替进程核验。

封存在现有不可变 Audit 链追加精确事实指纹。被封存的失败 Job/Run、周期、token、费用与预算不改；
`model_usage_uncertain` 继续保留，零内部预算暴露不代表实际调用或套餐用量为零。
新请求仅对匹配封存及当前事实的精确旧 Run 解除历史结算阻塞，订单占用、其他未知研究、
未完成周期、未支持版本的未知失败、资金和风控守卫继续生效。原任务不能通过正常重试/领取入口复活。
重复相同调用不追加 Audit；一项失败整个批次回滚。`sealed_research` 不是完整账户就绪或研究成功证明。
回退代码/服务时保留封存事实；旧版本可能重新阻塞入口，禁止删除审计来回退。

正式研究先完成五角色或再完成两角色 critique 后，后续调用用量未知时，可保留已知 token 下界。
须校验完整前序角色及引用、失败终态哈希、失败阶段、冻结输入、角色 token 合计，且观察编译器
从原冻结事实重建的失败阶段请求必须与已持久请求哈希精确匹配。当前代码读回无法匹配时拒绝，
不据重建推断历史响应或总用量；更改请求编译规则后，旧 partial 记录可能再次被拒绝。

精确绑定同一终态手动请求时，正常封存入口在同一事务调用原生关闭：仅取消从未尝试、没有输出
及租约的剩余研究，再追加请求 unavailable。其他 active/preparing/unknown 请求仍阻塞。
任一关闭守卫失败，新增 Audit、取消及请求事件一并回滚；重复成功操作不新增事实。
该恢复不启动新研究、周期或订单，不自动解除预算、账户占用或执行锁。

## 新正式定时周期的失败收尾

本地候选在 v8 普通定时研究续接发现失败任务时，复用上述原生取消逻辑收尾其余从未领取的任务。
不改变 `RESEARCH_OUTPUT_NOT_ACTIONABLE` 或原失败任务；不触发模型、来源、综合、决策或订单。
旧版本、手动关联周期及经济通道仍使用原入口，不纳入这项自动收尾。

自动路径对现有预算日锁使用非阻塞尝试，再以 `SKIP LOCKED` 重新读取 Job。预算或任务锁繁忙时
保留对应任务；终态事件只记录实际 `unused_research_cancelled` 数量，检查完成不表示全部任务
已结算或账户可用。不会等待正在执行的 Worker，也不把领取后的研究清零。

一项守卫拒绝时 savepoint 撤销整批收尾，并在原 unavailable 事件记录固定
`UNUSED_RESEARCH_CLEANUP_REJECTED`；预算、输出、研究事件与尝试不留部分取消。
数据库异常仍向上传播，不能伪装成收尾成功。重复终态续接只读原事实，不补派发或反复取消。
繁忙后遗留任务可经既有显式 `cancel-unused-research` 入口重新核对收尾；未知用量仍保持阻塞。

## 正式研究租约过期后的精确收尾

正常正式 resume 会检查原周期内 running 研究的租约。只有租约已过期、首次 Attempt 与 Job/Run/
冻结模型及预算完整绑定、没有研究输出/事件且用量未结算时，才将原 Attempt 记为 lost、Job 记为
dead_letter，并追加 `RESEARCH_LEASE_EXPIRED_RESULT_UNKNOWN` 本地终态。不重新领取，不调用模型；
已完成股票结果保持原样，未知 token、费用和预算 reserved 保留。活跃锁跳过，绑定不符拒绝并回滚。

该恢复使周期 unavailable；仅本次确实恢复了过期研究时，手动周期也可取消其余确定从未领取的
queued 研究。经济通道不进入这项清理。清理不关闭未知手动请求，不接受未知用量，也不解除新研究
准入。原有历史封存须满足其独立证据要求，不能将租约过期当作上游完成、进程退出或用户接受。

Worker 在每阶段、SDK 启动后和实际模型派发前检查原 wall-clock 租约；Mac 睡眠后即使 monotonic
超时尚有余量，也不得在失效租约下继续派发。此保护不改变超时、预算、系统睡眠设置或执行权限。
本次没有 schema 变更；代码可回退到前一镜像，已追加的收尾事实及未知预算应保留。


## 本地失效尝试的显式同日封存

`RESEARCH_LEASE_EXPIRED_RESULT_UNKNOWN` 是正常恢复追加的本地失联终态；它不含 SDK 原始
阶段回执。该记录不能使用 `--same-day` 原有的 SDK 证明分支，更不能补造 `stage_input`。
经明确接受具体未知用量后，可显式选择新增证明种类：

```bash
uv run --project engine nexus-engine-manual-paper --repo-root "$PWD" \
  seal-failed-research --cycle-id <原失败周期ID> --run-id <已确认停止的RunID> \
  --accept-unknown-usage --same-day --expired-attempt
```

这是 `paper_expired_attempt_close_v1` 独立审计，不修改默认跨 UTC 日政策或
`paper_same_day_close_v1` 的 SDK 证明语义。日期翻页仅改变旧政策适用性，并不补出上游结果。
新增证明继续要求 common 周期/模型/账户/内部零单价与零预留守卫，且精确验证原生首次失效
Attempt、worker/token/fence/起止时刻、JobKey、dead_letter/LEASE_EXPIRED、唯一失败输出与事件
及哈希。额外尝试、角色输出、伪装原因、用量已改写、非 reserved 预算或活跃租约均拒绝。

首次接受沿既有生命周期锁、schema 锁和账户锁，事务前后重新检查研究进程静止；原 Job 行锁和
执行 fence 保证晚到 Worker 在业务回调前被拒绝。正常宿主 start/stop 共享生命周期锁；直接运行
宿主不能绕过数据库账户准入或旧 Job 终态。进程静止检查本身不代替这些持久化执行约束。
封存审计和原生 manual unavailable 收尾同事务；任一下游拒绝整体回滚。NVDA 等已完成成果、
目标未知用量及预留不变；仅确实从未调用的其他研究可沿既有取消路径清零。

同一回执读回绑定原接受时点、原证明种类及旧事实集合；合法新请求不影响其有效性，也不要求
新生产者退出。迟到旧事实使豁免失效，但不恢复旧任务执行资格。账户准入通过与新输入时效、
可用预算、行情、交易时段及宿主就绪分别验证，封存不启动任何新模型或订单。

无 schema 迁移；回滚应用保留原审计、失败和预算。旧代码不认识新 schema 时会拒绝后续准入，
不能通过删除审计、回写旧事实或释放预留规避这一限制。
