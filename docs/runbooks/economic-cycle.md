# 隔离经济周期入口

身份登记：读取已冻结的协议和 VersionBinding，创建两侧独立合成账户、各 10000 USD 的初始现金账本、正常初始基线审批，以及协议的 24 个槽位。`registered_not_started` 不代表研究、周期、共同窗口或内部执行已启动，也不代表经济评价或样本外验证通过。

## 登记

先使用既有协议与版本绑定入口在同一隔离库准备权威。目标必须是本机的 `nexus_diag_economic_protocol_*` 或测试框架管理的 `nexus_test_<32位小写十六进制>` 数据库；新登记拒绝已有业务周期、研究任务、订单和券商绑定。不接受实际账户 ID、自由资金金额、prompt、model、任意槽位或解除执行锁的参数。

数据库 URL 文件须由当前用户拥有，权限为 0600，不能是符号链接，内容为无 query 参数的本机 `postgresql+asyncpg` URL。CLI 同时核对 URL 数据库名和服务器实际 `current_database()`，不从环境变量补写或覆盖连接目标。

```sh
uv run --project engine nexus-engine-economic-cycle register \
  --database-url-file /absolute/private/path/database-url \
  --expected-database nexus_diag_economic_protocol_example \
  --protocol-hash <已冻结协议的64位hash> \
  --version-binding-hash <已冻结版本绑定的64位hash>
```

相同协议和绑定重复调用只校验并读取已有身份、槽位和基线，不重复出资或创建账户；同协议不同绑定拒绝。已有登记的历史回执优先于空业务库检查，因此后续出现业务 Job 不会令正常历史回执失效。新登记必须早于第一个冻结槽，不能改日期或创建替代槽。两侧初始化、初始审批、身份、全部槽位和审计在一个事务提交，任一失败全部回滚。

成功输出只包含评价 ID、协议/绑定 hash、侧数、计划槽数和固定状态；不包含账户事实、凭据或模型内容。失败只输出固定安全错误码。

## 首槽双侧研究准入

```sh
uv run --project engine nexus-engine-economic-cycle start \
  --database-url-file /absolute/private/path/database-url \
  --expected-database nexus_diag_economic_protocol_example \
  --pair-slot-id <已登记的不可变槽位UUID>
```

此入口只接受登记槽位 ID，不接受日期、账户、资金、model、prompt 或任意候选参数。它读取数据库时钟，未到冻结槽或已超过五分钟准入窗口时拒绝新启动；已有双侧周期优先读回，不重放。正常来源权威必须满足既有日历、候选、风险和研究快照合同，不因隔离评价放宽。

首次启动在一个事务内完成整对预算、两侧正常候选批次、周期绑定，以及每侧两只标的的原生研究 Run/Job 和预算转移。周期侧别绑定先于 Run/Job；任一侧准入失败，整对回滚。所有研究使用已冻结的共享模型，快照必须属于当前周期，预算必须属于当前侧与槽。`researching` 仅表示四个研究任务已准入，不表示模型已经运行或研究结论合格。

受控验证使用合成来源归档与测试时钟，实际经过原生研究 Worker、SDK 分阶段传输替身、两侧各两份研究终态，再调用原生综合准入和综合 Worker。共享研究模型保持冻结；组合提示按持久化 lane 绑定选择，各自版本、内容 hash 与实际记录一致。普通历史回执、终态和下游读取仍要求正常固定提示版本，不接受经济周期的自由覆盖。综合 SDK 超时后保持未知用量及预算占用，重复调用不重新派发。

这些验证不包含自然数据或真实模型调用，受控输出为观察/推迟比较，也不证明策略有效。正常 pair resume 已接通研究/综合/原生决策与目标准入；第一共同窗口冻结与拒绝门禁已有受控验证；共享归档与第一共同窗口的原生消费已有隔离受控验证；整对首窗推进与不可比只读结果见下节；页面链仍未交付。初次登记仍要求空业务库；后续新 hold、首次启动及待续接阶段核对所有周期、研究/综合 Run、Job 和订单是否属于同一登记身份。无关业务、借用 Run 的重复 Job 或券商绑定拒绝；已有 exact hold 与终态周期可以只读查回，但不授予新阶段准入。首次启动在消费已有 hold 前独立执行归属检查。多日受控验证现覆盖第二个冻结交易日：追加当日双边报价/原件、前一完整交易日日线及当日风险查询权威后，正常 start→四研究 Worker→两综合 Worker→正常 resume 产生双侧 completed NO_ORDER_REQUIRED。旧市场证据拒绝准入；第二日定价已过期时，即使两候选来源齐备也拒绝，且保留首日事实。跨日维持同一 Worker 启动身份，初次出资、旧 manifest、重复回执及 Job 数量核对通过；没有改写旧来源或续长定价。来源与 SDK 仍为合成夹具，不能称自然多日可靠、成交或经济有效。

## 持久化续接

```sh
uv run --project engine nexus-engine-economic-cycle resume \
  --database-url-file /absolute/private/path/database-url \
  --expected-database nexus_diag_economic_protocol_example \
  --pair-slot-id <已登记的不可变槽位UUID>
```

入口仅读已登记的双侧 cycle、冻结协议及数据库时钟，不接受调用者指定预算、模型或时间。按账户 UUID 顺序先取得原内部模拟账户锁，再取 cycle 与 pair 锁；两侧续接在一个事务内完成。复用正常 Schwab resume 的 Job/Run/Output→综合准入→决策→目标/计划链，CLI 不执行 Worker、模型、行情采集或成交。queued/running 仅报告等待；失败或未知终态保持原事实，不新建替代 Job。回执分别提供两侧状态和固定结果码，异步进展不一致时总状态为 partial。

旧正常 `resume_once` 入口识别经济归属后同样使用冻结额度及数据库时钟，普通设置不覆盖经济权威。非经济周期保留原额度、时钟和锁逻辑。完整 no-trade 可正常落为 completed / NO_ORDER_REQUIRED；不能用该结果证明自然成交或策略有效。有订单时须完成共同窗口冻结、全部归档与原生消费准入；当前候选尚未合入部署，不能激活真实经济运行。

## 第一共同窗口冻结

```sh
uv run --project engine nexus-engine-economic-cycle freeze-window \
  --database-url-file /absolute/private/path/database-url \
  --expected-database nexus_diag_economic_protocol_example \
  --pair-slot-id <已登记的不可变槽位UUID>
```

入口只接受受保护连接和已登记槽位，不接受时间、窗口边界、账户、任意 peer 或后续序号。先按两账户 UUID 排序取得内部模拟锁，再取 pair 锁；读取双方正常 Run/Job/Output、合格周期事件、决策和首次 submitted 订单的真实可用时刻。以双方最大资格时刻导出下一整分钟起的首个五分钟窗口，不能把 now 纳入资格而滑窗。冻结前和写入后均读取数据库时钟；若未提交窗口在写入过程中跨过开始时刻，只回滚该 savepoint，再以相同资格保留 missed，不重派模型、行情或旧周期。

双方完整合格不交易返回 not_required，不建虚假行情窗口；一侧不交易允许另一侧的已 submitted 精确订单集合冻结。未完成、过期、错身份或无合法窗拒绝。frozen/missed 及订单关联不可修改，重复冻结读取同一回执，并核对完整订单集合、侧别、账户、标的、决策、事件、研究/综合输出及实际资格上界。0071 的 deferred 约束拒绝缺少任一订单关联，引用 prepared 等未就绪事件不能成为窗口权威。

原生采集 scope 识别经济归属后只接受已冻结窗口；缺窗口或 missed 不回退普通单侧窗口。执行器保留原幂等回执优先读回，并在新推进前识别账户和周期归属，拒绝缺窗口、缺归档或归档冲突。完整归档须经过下述原生消费资格校验；冻结本身不授予成交许可。首窗只覆盖当时已 submitted 的订单；已确认部分成交后的后续窗口见下节。卖出后新增买单的受控流程与边界见后续新阶段节。

受控验证使用合成 AAPL/T2 来源、数据库时钟传输控制和 SDK 替身，实际经过正常 Worker/续接/CLI。不同完成时点、双交易、单侧不交易、双不交易、首窗错过、写入跨开始时刻以及数据库拒绝已覆盖；不证明真实行情、自然成交、策略有效或样本外通过。

## 同窗共享归档

使用既有正常 `nexus-engine-agent-paper-once collect-window --cycle-id <经济侧cycle UUID> --instrument-id <该侧已冻结订单的Instrument UUID>`，配置仍由正常入口读取受保护本地配置，不接受自由窗口、peer、时钟或解除锁参数。此候选的新写入仅允许既有经济诊断库或框架创建的测试库，业务库不获得采集许可。请求中标的用于选取返回绑定，实际采集集合由共同窗口的全部精确交易订单导出；多标的周期必须明确指定标的 ID。

先校验不可变窗口及完整既有绑定，有效历史直接读回；只有新声明及最终新绑定才核对运行隔离。短事务持久化一个 AuditEvent 单次采集声明，提交并释放数据库会话后，每个实际标的只调用一次原 provider。复用正常五分钟严格资格及原件/normalized 归档，原件必须逐字节读回一致；不同标的不能共享 raw、manifest 或来源权威。只有全部标的完成后，短事务复验原权威，统一持久化正常价格权威、manifest 及各自订单绑定。

已有完整回执不重采；未完成声明返回 ECONOMIC_WINDOW_COLLECTION_UNKNOWN，不以新目录、请求或重试替代。窗口结束前拒绝声明；采集或归档失败保留声明，绑定事务失败回滚本次未提交绑定，不回滚或改写既有历史。正常 CLI 只输出固定安全码，不透传来源错误、原始响应或凭据。

共享归档不产生 fill/ledger，不释放预留，不授予执行许可。原生执行器随后独立核对完整资格，详情见下节。受控传输、测试时钟及合成账户通过，不等于自然行情或自然成交验收。

## 第一共同窗口原生消费（隔离受控验证）

既有 `run_once` 产品服务入口及原生执行器识别持久化经济归属，不能用调用者指定的 peer、账户或窗口代替权威。整对 `advance_economic_pair` 编排及对应候选 console 见下节；本节单订单消费验证与整对编排验证分别记录。

新成交先核对完整共同窗口、全部订单绑定、实际诊断库隔离、原始研究意图时效、正常日历及内部账户投影。正常经济入口从数据库取得实际时钟；原生执行器同时核对实际时钟，旧请求时间不能绕过研究到期或实际收盘。全部标的复用原生成交模型及来源资格，返回已校验的窗口对象给原执行器，避免资格校验后再次自由选择报价。同一标的双方的报价、来源与容量必须一致，且与已提交的正常执行窗口一致；报价漂移固定拒绝，不改写第一侧成交。

每侧继续使用自身原生订单、预留、成交、账本和投影，消费只拿自身账户锁再取得共同窗口锁，不拿另一侧账户锁。显式取消及收盘释放遵循同样锁序，但不要求归档齐备。终态和精确历史回执优先读取，不因当前时效或另一侧变化重新成交。部分成交保留原生余量及资金占用；收盘按原规则取消余量并释放预留，已提交成交和持仓保留。

受控 PostgreSQL 场景使用两只合成标的、两个内部账户，正常研究/综合 Worker→订单→共同冻结→共享归档→原生消费→账本投影。覆盖完整/部分成交、历史幂等读回、旧请求时间、收盘释放、报价漂移及跨侧取消竞争。单侧已提交后另一侧拒绝时保留真实非对称结果，不制造补单；整对不可比读取见下节，后续窗口见下节，四页仍待交付。测试通过不代表真实来源、自然成交、策略有效或整体日常可用。

## 整对共同窗推进与只读状态（候选）

```sh
uv run --project engine nexus-engine-economic-cycle advance-window \
  --database-url-file /absolute/private/path/database-url \
  --expected-database nexus_diag_economic_protocol_example \
  --pair-slot-id <已登记的不可变槽位UUID>

uv run --project engine nexus-engine-economic-cycle execution-status \
  --database-url-file /absolute/private/path/database-url \
  --expected-database nexus_diag_economic_protocol_example \
  --pair-slot-id <同一槽位UUID>
```

两入口均不接受任意账户、peer、时间、窗口边界或后续序号。`advance-window` 从最新已冻结共同窗口与全部严格绑定导出完整订单集合及固定原生操作身份；实际诊断库隔离通过后，短事务只声明一次整对推进，各笔原生订单在独立事务中提交。为保持独立提交，服务接口接收 session factory，不能把整个 pair 包在调用者的一个事务里。

已经存在推进声明时只读取原生精确回执及原始成交，不再调用消费。确定失败后停止未尝试订单，保留已提交成交、原有预留与账本，不制造补单；已提交后返回固定错误也先读原事实，不误写失败。未知错误、中断或回执丢失保留原声明及未知缺口，不授权重新推进。完整回执的订单状态与正常不可变原生回执交叉验证，固定失败码仅存于审计；不能用审计自造成交事实。

结果逐订单给出实际状态，并逐侧区分已成交、部分、未知、不可用及合格不交易。有窗口时，只有已验证共同窗口中没有订单且原 NO_ORDER_REQUIRED 资格完整的侧才标 no_trade。已成交且后续失败/未知时 comparison_status=incomparable；部分成交仍为 incomplete；全部订单完成仍为 not_evaluated，不代表策略有效或样本外通过。

`execution-status` 使用 REPEATABLE READ READ ONLY 事务，无账户/窗口写锁、不声明推进、不调用模型或采集、不写账本。未声明且没有原生执行事实时为 not_started，已声明未完成时为 unknown；固定失败后重复查询仍保留原结果。无窗口时，只有双方原始周期均 completed / NO_ORDER_REQUIRED，连续事件 hash、正常研究/综合输出、决策、目标激活回执和完整成功 Job 集合全部按自身账户复验通过，才返回 completed、window_id=null、两侧 no_trade 与空订单；comparison_status 和 economic_status 仍为 not_evaluated。未完成、单侧失败或有订单但无窗口仍报告 WINDOW_REQUIRED；伪造或模糊归属报告固定 UNKNOWN，不创建假窗口或推进回执。历史读取保留原时点，不因当前时间过期制造新的准入。既有复星价格证据校验短事务保护 manifest/calendar 一致性，事务结束释放；这些来源锁不授予账户或执行窗口写入。归档未齐或身份错误仍报告固定安全缺口，不回退普通执行。

当前范围是已冻结并完整归档的首窗、原订单余量后续窗及卖出后新买单窗口，包括单侧合格不交易；双侧均不交易且不创建窗口的结果汇总已在候选入口实现；四页接线仍需后续交付。后续窗口候选实现见下节。本候选尚未合入或部署，不用于激活真实经济运行。

## 部分成交后的后续窗口（候选）

```sh
uv run --project engine nexus-engine-economic-cycle freeze-next-window \
  --database-url-file /absolute/private/path/database-url \
  --expected-database nexus_diag_economic_protocol_example \
  --pair-slot-id <同一不可变槽位UUID>
```

序号由数据库在双账户及配对锁内导出，不接受调用者指定序号或时间。已有未完成或 missed 窗只读原冻结回执；不得另开窗口绕过它。前一窗必须存在整对完成审计，且每笔原生精确执行回执均已确认完整或部分成交；未知、取消、不完整或单侧失败仍拒绝继续。

下一窗资格时刻取原首窗资格、前窗完成审计、所有原订单的实际执行事件及原生成交窗口的最大实际可用时刻；开始是其后的下一整分钟，结束为五分钟后。采集与执行实际发生在前窗结束后，因此此窗可能与前窗存在间隔；不以调用者当前时刻滑动，也不回填过去。原研究意图和模型定价期限、原槽收盘界限都继续生效。冻结已迟则持久化 missed，原窗口不修改。

每个窗口保存前窗及完成审计的精确身份/hash、全部原订单的精确状态事件和对应真实成交窗口。只有仍有余量的订单关联新窗；已完成的订单不再采集或消费，也不被重新标为 no_trade。正常 collect-window 自动使用最新冻结窗的全标的集合，归档完成后使用 advance-window；execution-status 查询最新窗，历史服务仍能按原序号严格读回。

0072 保留普通订单的连续窗口约束。仅有精确经济共同窗、订单归档和实际前序成交窗口绑定时允许正时间间隔；原序号连续、时间单调及来源/feed/delivery 不变。沿用原生订单预留、成交、现金/仓位账本，不预用其他侧或未来卖出所得。完成所有余量依旧为 not_evaluated，不是经济或样本外验收。

## 边界与回滚

`register` 不建 cycle、Job 或预算；`start` 只创建研究任务与预算事实，本身不调用模型或行情。这两个入口均不建订单或成交；resume 可沿原生确定性准入生成目标、计划和订单/不交易决定，但不执行成交。上述入口不修改主线配置，不解除 `execution_locked=true`。窗口冻结和共享归档均不执行成交；原生消费已有隔离验证，整对首窗推进见上节，页面链仍待接通。

未提交的失败事务可自动回滚。已提交的身份与资金账本是不可变事实，不删除或重标历史；隔离测试库只能由创建它的测试生命周期清理。0070 降级仅允许没有经济身份/槽位/lane 事实的数据库，存在事实时保持拒绝。

0071 仅在窗口及关联均为空时可降级至0070；存在任何冻结或 missed 事实时拒绝降级。业务服务尚未应用此候选迁移；不通过删除事实回滚。

0072 有任何后续窗口事实时拒绝降级；没有后续事实才允许恢复0071首窗约束及普通原生连续链规则。不删除或改写成交、审计和旧窗口来回滚。
